## Evicted: § Staged-script resume, restage and stage failure

**Resume:** a `resumeFromRunId` resume of an `--args`-staged script needs **no** re-passed args — write-if-absent guarantees the resume dispatches the same embedded bytes, and the staged script's top-level entry validation re-runs against them (the exact incident shape #1134 names, where an args-less resume died at entry validation despite a healthy journal). **Residuals:** a script staged **without** `--args` keeps today's behavior — an args-less resume of it still dies at entry validation, because the embedded fallback exists only when `--args` staged it; and this note sanctions **no new resume path** — `resumeFromRunId` stays `held:phase-incomplete`-only per **Resume vs. recovery relaunch** ([resume-and-recovery.md](resume-and-recovery.md)). Re-embedding **changed** args is a deliberate `--force` restage (write-if-absent otherwise reuses the staged file byte-untouched and warns on stderr that `--args` was ignored). **Stage failure:** an exactly-once anchor failure exits non-zero **naming the offending anchor label** — the remedy is to bring the shipped template and the stager back into lock-step (they version together); `--force` only re-runs the same substitution and cannot help.

## Comment strip and size floor (#2099)

The Workflow tool refuses any `scriptPath` over its 524,288-byte `scriptPath` cap (`SCRIPT_BYTE_CAP` in `stage-workflow.mjs`, pinned here by `stage-workflow.test.mjs` arm (r)), before entry validation runs. The shipped `workflow-template.js` alone crossed that cap at 0.21.11 (measured 525,209 bytes on 2026-09-06, about 250 KB of it full-line comments), so every launch that staged a fresh copy from that template was refused at dispatch. The stager now handles this with nothing to opt into:

- **Strip.** Before the anchor substitutions, the stager blanks every full-line `//` comment that sits in code state out of the staged copy. A line inside a string, a template literal (any `${…}` nesting), a regex literal or a block comment is never touched, and neither is a trailing comment. Each blanked line becomes an empty line, so the line count is preserved: a line number in a staged copy is the shipped template's line, plus the two prelude lines an `--args` stage adds after `meta`. The shipped template is unchanged; the strip lives only in the staged copy.
- **Fresh-stage floor.** If the assembled copy (stripped template, substitutions, and any embedded args) would still exceed the cap, the stager exits non-zero with `stage-workflow: staged script would be N bytes, over the Workflow tool's 524288-byte scriptPath cap (…)`, names the stripped-template and args sizes, and writes nothing. Remedy: slim the `--args` payload (split the memory blocks or plan slices across a smaller launch), never dispatch around it. If the stripped template alone is near the cap, that is a template defect: `stage-workflow.test.mjs` arm (p) pins 128 KiB of headroom under the cap and goes red first.
- **Reuse floor.** Write-if-absent reuses an existing staged file only when it is at or under the cap. An over-cap existing file (a 0.21.11-era stage) cannot dispatch, so the stager exits non-zero naming `--force` and leaves the file byte-untouched. A `--force` restage is a fresh, comment-stripped substitution: any injected stage in the old file is lost and must be re-applied, and a `resumeFromRunId` journal recorded against the old bytes no longer matches — a fresh launch, not a resume, follows such a restage.
- **Preflight.** `assert-args-complete.mjs --template <staged path>` reads the stripped copy the same way it reads the shipped template: the fallback-free interpolation census is unchanged by the strip (arm (p) pins it, occurrence counts included).

Measured on this template at 0.21.12: a staged copy is 274,663 bytes, 249,625 bytes under the cap; the measured over-size args class is ~104.5 KB. Decision record: [ADR 0037](../../../docs/adr/0037-run-scoped-staged-phase-scripts.md) decisions 2, 3 and 6, each with a 2026-09-06 amendment.
