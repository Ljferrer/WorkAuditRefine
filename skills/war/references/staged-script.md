## Fresh launch versus journal replay (#2300)

Before staging a new run or Recovery relaunch, follow [launch-identity.md](launch-identity.md): mint `runId` with `new-run-id.mjs` and use its new run-scoped directory and args payload. Same-day reruns are fresh runs too. Only journal replay reuses the prior ID and staged bytes; a new directory prevents write-if-absent from silently reusing old embedded args.

## Evicted: § Staged-script resume, restage and stage failure

**Resume:** a `resumeFromRunId` resume of an `--args`-staged script needs **no** re-passed args — write-if-absent guarantees the resume dispatches the same staged bytes, which load the same args sibling script (the args sibling section below), and the staged script's top-level entry validation re-runs against them (the exact incident shape #1134 names, where an args-less resume died at entry validation despite a healthy journal). **Residuals:** a script staged **without** `--args` keeps today's behavior — an args-less resume of it still dies at entry validation, because the embedded fallback exists only when `--args` staged it; and this note sanctions **no new resume path** — `resumeFromRunId` stays `held:phase-incomplete`-only per **Resume vs. recovery relaunch** ([resume-and-recovery.md](resume-and-recovery.md)). Re-embedding **changed** args is a deliberate `--force` restage (write-if-absent otherwise reuses the staged file byte-untouched and warns on stderr that `--args` was ignored). **Injected stages:** every stage writes a `<staged>.sha256` sidecar beside the staged file, holding the digest of its bytes. `--force` overwrites only a file whose sidecar matches. If the file was hand-edited (an injected stage) or has no sidecar, `--force` exits 1, names the override flag `--discard-injections` and writes nothing. Re-apply the stage after a `--discard-injections` restage, or keep the file and skip the restage. **Stage failure:** an exactly-once anchor failure exits non-zero **naming the offending anchor label** — the remedy is to bring the shipped template and the stager back into lock-step (they version together); `--force` only re-runs the same substitution and cannot help.

## Comment strip and size floor (#2099)

The Workflow tool refuses any `scriptPath` over its 524,288-byte `scriptPath` cap before entry validation runs. The cap is `SCRIPT_BYTE_CAP` in `stage-workflow.mjs`, pinned here by `stage-workflow.test.mjs` arm (r). The shipped `workflow-template.js` alone crossed that cap at 0.21.11. It measured 525,209 bytes on 2026-09-06, about 250 KB of it full-line comments. So every launch that staged a fresh copy from that template was refused at dispatch. The stager now handles this with nothing to opt into:

- **Strip.** Before the anchor substitutions, the stager blanks every full-line `//` comment that sits in code state out of the staged copy. It also drops the leading spaces and tabs of every line that starts in the top-level code frame. Some lines keep every byte: a line that starts inside a string continuation, a template literal (any `${…}` nesting), a `${…}` body or a block comment. A line inside a regex literal is never touched, and neither is a trailing comment. One known scanner residual is recorded beside the scanner: a `/` right after a closing `}` is read as a regex. So a template literal opened on that same line is missed. A `//`-led line inside it can be blanked, and its indented lines can lose their indent. No such line exists in the template today, and `stage-workflow.test.mjs` arms (p) and (s) are the guard. Arm (s) is the `indent-strip:` rows, with four oracles over the shipped template and a mutant row per scanner branch. Each blanked line becomes an empty line and no line is removed, so the line count is preserved. A line number in a staged copy is the shipped template's line, plus the one args loader line an `--args` stage adds after `meta`. The shipped template is unchanged; the strip lives only in the staged copy. Room: this file restates no byte count. `stage-workflow.test.mjs` arm (p) measures the stripped template against the cap and its `ARGS_HEADROOM_BYTES` reserve, and its comment carries the reserve's history.
- **Args sibling script (D38).** Under `--args <file>` the args never enter the staged copy. The stager writes them to `<staged basename minus .js>.args.js` beside it: a meta statement, then `return` of the validated args JSON, with its own `.sha256` sidecar. The staged copy carries one loader line after `meta`. When no args were dispatched, it loads the sibling through `workflow({ scriptPath })` and keeps any load error instead of throwing. The rewritten args fallback, inside the engine's top-level `try`, then throws a named `args sibling load failed` error, which the engine returns as `held:workflow-error`. Dispatched args still win and skip the load. The pair moves together. A reuse of a staged file whose sibling is missing exits non-zero and names `--force` and `--discard-injections`. `--force` refuses when either file's sidecar does not match. The next fresh stage overwrites an orphan sibling with no staged file beside it.
- **Fresh-stage floor.** The assembled copy is the stripped template, substitutions and the loader. If it would still exceed the cap, the stager exits non-zero with `stage-workflow: staged script would be N bytes, over the Workflow tool's 524288-byte scriptPath cap (…)`. It names the stripped-template size and writes nothing. The args sibling is its own `scriptPath`, so it is held to the same cap. An over-cap sibling exits non-zero naming the args JSON size and writes neither file. Remedy for that one: slim the `--args` payload (split the memory blocks or plan slices across a smaller launch). Never dispatch around it. If the stripped template alone is near the cap, that is a template defect: `stage-workflow.test.mjs` arm (p) goes red first.
- **Reuse floor.** Write-if-absent reuses an existing staged file only when it and any args sibling beside it are at or under the cap. An over-cap existing file (a 0.21.11-era stage) cannot dispatch. So the stager exits non-zero with the remedy `--discard-injections` and leaves the file byte-untouched. Such a file predates the sidecar, so `--force` refuses it, as it refuses any file with no sidecar or a hand-edited one. A `--discard-injections` restage is a fresh, comment- and indent-stripped substitution. It drops every injected stage, which you must re-apply. A `resumeFromRunId` journal recorded against the old bytes no longer matches, so a fresh launch, not a resume, follows such a restage.
- **Preflight.** `assert-args-complete.mjs --template <staged path>` reads the stripped copy the same way it reads the shipped template. The strip leaves the fallback-free interpolation census unchanged (arm (p) pins it, occurrence counts included). It also leaves unchanged the args-field set that the column-0 top-level binding reader derives. Arm (s)'s `indent-strip: the args-field census is unchanged` row pins both on the indent-stripped copy.

History, not a live measure: at 0.21.12 a comment-stripped copy of the shipped template measured 274,663 bytes. That was 249,625 bytes under the cap, against a measured over-size args class of ~104.5 KB. The live measure is arm (p)'s headroom floor. Decision record: [ADR 0037](../../../docs/adr/0037-run-scoped-staged-phase-scripts.md) decisions 2, 3 and 6, each with a 2026-09-06 amendment. It also holds decision 2's 2026-11-04 amendment (#2613, the indent strip) and the 2026-11-09 amendment (D38, the args sibling script).

## Args-complete preflight: which template it reads, exit codes, and the entry check

By default it reads the SHIPPED template beside it; the stager's comment and indent strip plus substitution leaves the interpolation set and the args-field set unchanged (pinned by `stage-workflow.test.mjs` arms (p) and (s)), so the default path is deliberate — but a run whose staged script carries an approved injected stage must re-check against what actually dispatches: re-run with `--template <the stager's printed staged path>`. Exit 0 ⇒ dispatch; exit 1 ⇒ the args omit a named field the template would interpolate as `undefined`, or a row fails the template's provenance floor — fix the field(s) or stamp the row at its source, never dispatch over it; exit 2 ⇒ a tooling error (unreadable/unparseable input, or a template source yielding zero interpolations — it refuses to certify against nothing), never a pass. This preflight is the belt; the template's own entry validation is the suspenders (a missed preflight still dies loud at entry, zero spawns). Dispatch in one of two shapes: pass the parsed args object as the Workflow `args`, or pass no `args` over an `--args` staged script; never pass a file path string as `args`, because the template cannot read a file, so such a launch dies at entry with 0 agents. In a linked worktree launch the staged script already lives under the run root ([setup.md](setup.md) § Run root); no copy is needed.
