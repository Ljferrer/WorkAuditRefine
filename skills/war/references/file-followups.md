# File-followups dispatch — filing procedure

Read when dispatched a `file-followups` run (pointer on `agents/war-refiner.md` § File-followups
dispatch). Evicted from that card under its prompt-surface byte budget (ADR 0042); per ADR 0047
adjudication O(1) this file is best-effort enrichment, never the sole carrier — the dispatched
prompt carries the same instructions verbatim, and the card keeps the never-decline rule and the
`FOLLOWUP_FILING_RESULT` return shape inline (§ Return).

**Preflight first** (ADR 0026): run the dispatched `gh-preflight.sh` line before any gh write; on exit 2 (tooling error) or exit 3 (account mismatch), return what you have and file **nothing**. **Dedup first**: `gh issue list --label war-followup --state open` — a row matching an open issue (exact title, or same file + root cause) gets a **corroboration comment** there, never a new issue; reuse its number. Cluster remaining rows by file + root cause (rows carry file/line/`seats`, and a consolidated row also carries its **merged corroborations** — each merged-away finding's title and rationale, which must reach the issue body, never drop; the engine's collapse is cross-seat only — same-seat rows never merged). `seats` entries render seat+task (`<seat> (task <id>)`, both when present), with a bare `task <id>` or `'unattributed'` for seatless rows. File one `war-followup` issue per **cluster** — members share one issue number. Return ONLY `{ filed: [{ n, issue }], clusters: [{ ordinals, issue }] }` — a fail-open evidence return (unmatched entries stay `issue: null`; the Checkpoint floor catches them; `clusters` covers every ordinal exactly once), never a `MergeResult`. EACH filed issue body carries, as its **first line**, `Demote-Reason: <value>` copied verbatim from the row's `filed-by` field — the engine's `demote:<reason>` prefix (`DEMOTE_REASONS`, canonical in `land-decision.mjs`) on an engine-demoted row, `demote:floor-skipped` on a seat row the intake floor never judged (a failed or absent diff probe, the escalation arm, or the sweep panel's polish pseudo-task), or `seat-filed (barrier: <tag>)` otherwise; a clustered issue lists one such line per member row. EACH filed issue body ends with an `## Evidence artifacts` section carrying, per member row, the pinned sha (a `requiresTest:false` task's is its landed integration tip — never gate-audited, the D7 skip), the file path (with line when present), the raising seat lenses (a seat entry's lens follows the FAMILY-PREFIX rule: a seat label whose first `:`-segment is `gate-audit` yields the lens `execution-evidence` whatever its trailing segments — a phase-level segment like `phase-1` or a dispatch suffix like `integrated-tip`/`end-state` is never a lens; otherwise the lens is the trailing `:<lens>` segment, read before any ` (task <id>)` attribution suffix; a trailing `:rebut` is a dispatch label, never the lens — take the segment before it), and the audit round — every value copied verbatim from the candidate rows (`unrecorded` stays `unrecorded`, never invented); on the dedup arm the same lines ride the corroboration comment instead.

**Ruled-ask filing parity (#1550, ADR 0013 amendment 2026-08-25).** This dispatch consumes the engine's consolidated `minorsFiled` rows ONLY — a parked `asks[]` record is structurally excluded: an **unruled ask is never filed**, by this dispatch or any other route. Ruled asks — parked decision-shaped questions the operator ruled at the Checkpoint strike-list gate — file **Lead-side** (SKILL.md § Checkpoint). Since the **ADR 0013 amendment 2026-08-27** that filing is **filing-on-non-execution**: a ruled ask whose fix is fully specified executes in this run (next-phase decompose injection, or the final phase's polish-style dispatch), and an issue is filed **only** on cannot-execute (no vehicle, cross-task, budget) or execution-failure, the ruling recorded in it either way — never silently, never as default litter. A filed ruled ask keeps **filing parity** with the rows above: the same dedup-first discipline (an open `war-followup` match — engine-filed rows included — takes a corroboration comment, never a duplicate issue), and the same `## Evidence artifacts` section per filed issue (pinned sha, file path with line when present, raising seat lenses, audit round — every value verbatim, `unrecorded` stays `unrecorded`), plus the ruling itself: the question, the fork, and the operator's ruling with its moment.
