# WAR data contracts

Every agent returns **only** its JSON object (no prose). The Workflow passes these as the `schema` to `agent()`, so the StructuredOutput tool validates and the model retries on mismatch.

## WorkerResult — `war-worker` and fix-workers
```jsonc
{ task_id, branch, worktree, head_sha,
  status: "implemented" | "blocked",
  tests: { added: ["path"], command: "uv run pytest ...", passed: true },
  acceptance_criteria_covered: ["<end-state id>"],   // claimed End-state ids (A1/D9, the 2026-08-05 precision-chain plan): the numbered `## Commander's Intent` / `## AI-Commander's Intent` End-state conditions this task claims to satisfy; each id is the condition's 1-based ordinal in the intent's numbered End-state list, rendered as a string ("7"), resolving to that condition's verbatim text — the `plan_ref` / `endStateAttestations.condition` / handoff `endState.condition` key; [] when the task claims none; the gate-audit seat cross-checks the claims (cross-check produced by its Task 3.2, landed 0.17.0)
  files_changed: ["path"],           // each path worktree-relative — never absolute, never main-checkout-rooted (the engine normalizes a main-rooted report and escalates any other absolute)
  ace_diff_files?: ["path"],         // (ace-family workers and the phase-close sweep's polish worker) the GIT-derived changed-file list of the ace commit — `git diff --name-only HEAD^ HEAD` after the single commit. The delta-scaled re-audit's ONLY scale input: a set inside the batch findings' own file set re-runs just the originating seats and transfers the other seats' approvals to the new sha; the delta-scaled re-audit treats files_changed as a CROSS-CHECK only. Absent, empty, or disagreeing ⇒ the FULL panel re-runs (fail-closed). The ONE consumer with a different precedence is the sweep's landed-row check (`sweepTouched`): it prefers ace_diff_files and falls back to files_changed as a SOURCE when ace_diff_files is absent or empty. The terminal-pass worker is not asked for it (no consumer reads it there)
  notes: "anything the auditor should know",   // convention, no schema change (ADR 0052): the first-pass worker writes a `Critical path:` block then `Ignore for now:` here (shape: `backward-chain-worker.md` `## Chunk shape`); a fix-applying worker echoes its fix commit body block here byte for byte (the bullet below): the engine reads only `notes` (the Workflow sandbox has no git) and threads the block in the history digest from corrective round 2
  blocked_reason?: "present iff status==blocked — the ambiguity/contradiction" }
```
- **The fix commit body shape** (ADR 0052, no schema change): every fix-applying worker (FIX_NEEDED, the ace family, the floor family, the phase-close sweep, the terminal pass) writes one block `Outcome:` `Chain:` `Bottleneck:` `Fix:` `Ignore for now:` into the fix commit body, in that order, and echoes the same block into `notes`. Canonical shape and field meanings: [backward-chain-fix.md](backward-chain-fix.md) `## Round 1`, never restated here. The auditor reads the commit body with its own read-only git; the engine reads `notes`. Both readers must see one text.

## ENV_OUTCOME — the uniform return for all three `provision` dispatches
Every `provision`-mode refiner dispatch — the **phase git-topology barrier** (`provision:phase-<id>`), the **per-task provision-run** (`provision-run:<taskId>`), and the **phase-close polish worktree** (`polish-worktree:phase-<id>`) — returns this same shape:

```jsonc
{ ok,                   // true iff every dispatched subcommand exited 0 (barrier: OR every non-zero exit was a classified STALE_REMOTE marker)
  taskId?,              // (provision-run) the task whose worktree was being provisioned
  failedCommand?,       // the subcommand/step that exited non-zero — VERBATIM (the evidence gate matches it)
  exitCode?,            // its exit code (a NUMBER; a non-zero value is required for an env-block)
  stderrTail?,          // tail of its stderr (the escalation / the script's die text)
  provisionSource?,     // (provision-run) where the list came from: explicit|manifest|ci|onboarding|structural|none
  preMerged?,           // (barrier, recovery) [taskId] — tasks already-integrated on the adopted branch, skipped
  staleRemote?,         // (barrier, always-on) [{ task, remoteSha, frozenTip }] — classified per-task stale-remote markers
  worktreeHygiene?,     // (barrier, ok: true only) [{ task, path, action: "repaired"|"detected", detail }] — reuse-path submodule-hygiene findings
  absorbCharges? }      // (barrier, always-on) { <task>: n } — the HIGHEST `Ace-Charge: <task>:<n>` trailer index on each task branch; seeds r.task.absorbRounds (absent/malformed ⇒ 0, logged)
```

- **Evidence gate (per-task provision-run).** An `ok: false` becomes an **`env-blocked`** task outcome ONLY with **execution evidence**: a `failedCommand` that trim-matches one of the dispatched `run.provision` steps (exact array membership, never substring) **and** a numeric **non-zero** `exitCode`. An `ok: false` missing that evidence — a missing/typeless result, refusal prose, a foreign/absent `failedCommand`, a non-numeric or an incoherent `exitCode: 0` — is **not** trustworthy: the provision-run throws inside the work thunk, the wave-loop-invariant catch converts it, and the task **escalates** (**`held:escalation`**, the evidence-gate message naming the task + `provision-run` carried verbatim in the escalation's `blocked`), never a fabricated `env-blocked`. (There is no `provisionList[0]` / synthetic-`exitCode:1` fallback — the template throws.)
- **Barrier / polish routing.** A barrier `ok: false` (or missing result) → `held:workflow-error` carrying the `stderrTail` (no topology ⇒ nothing in the phase can run — a hard stop, evidence or not). A polish-worktree `ok: false` (or missing) → **fail-open**: the sweep is skipped, the phase-close queue drains to `follow-up`, the phase still lands (never a hold).
- **Barrier recovery arrays (phase git-topology barrier only).** On an `ok: true` return the barrier may carry two OPTIONAL recovery arrays (spec §4.2/§4.4); a third, `worktreeHygiene`, is documented below:
  - **`preMerged`** — `[taskId]`. Present only on a **sanctioned recovery relaunch** (`args.recovery.sanctioned`, §Provisioning args): task ids proved by `task-integrated.sh`: integrated ancestry, a nonempty commit with the exact `WAR-Task` branch trailer, surviving net task-owned work without mixed later history, unchanged task/integration content across the union of every qualifying owned commit’s changed paths, and stable input refs (the Workflow sandbox has no shell). Outside `args.recovery.sanctioned === true`, unsolicited `preMerged` rows are logged and ignored; ordinary work/audit remains required. During sanctioned recovery the Workflow records each `merged` (terminal task status, **never** `landed`) with note `recovered: pre-merged on adopted integration branch`, enters it into `done` + `succeeded` + the bare-id `landed` list with one `auditLog` entry, and **dispatches no worker**; it does **not** enter it into the gate-audit set (no gate ran for it this run — the handoff `tipSha` fallback stays truthful). A `deps` entry of the re-dispatched task therefore satisfies the dep-block pre-check (no spurious `dep-failed`).
  - **`staleRemote`** — `[{ task, remoteSha, frozenTip }]`. **Always-on** classification (NOT gated on `args.recovery`): each entry is a per-task worktree-creation exit whose output carried the `STALE_REMOTE` marker (the marker token is the key, never the numeric exit code). The barrier continues provisioning the remaining tasks. The Workflow maps each to the existing per-task **`env-blocked`** status (worker never spawned) with the full two-direction recovery diagnostic — (a) adopt via `git branch <branch> <remoteSha>` + relaunch, (b) sanctioned `--reclaim-stale-remote` — plus the restore command `git push origin <remoteSha>:refs/heads/<branch>`. Siblings dispatch normally; a dependent follows the existing `dep-failed` semantics; the barrier does **not** halt the phase (ADR 0021's all-or-nothing topology barrier untouched). The classification rides the machine-readable return.
- **`worktreeHygiene`** (D20, #1381) — OPTIONAL array on a barrier `ok: true` return **only**: `[{ task, path, action: "repaired"|"detected", detail }]`, captured from the `WORKTREE_HYGIENE` marker lines an `ensure-worktree` **reuse** emits when a reused worktree's declared submodule is found dirty (repaired only on the killed-populate corruption signature at a gitlink-matched SHA; anything else is `detected` — reported, tree untouched). **Fail-open, no routing change:** the markers ride a zero exit — never a hold, never an `env-blocked`; absent means nothing was found. The Lead surfaces entries in the phase report.
- **`absorbCharges`** (absorb-budget, D5) — OPTIONAL map on a barrier `ok: true` return, **always-on**: `{ <task>: n }`, where `n` is the **highest** `Ace-Charge: <task>:<n>` trailer index on that task's branch (`git log --format='%(trailers:key=Ace-Charge,valueonly)' <integrationBranch>..<branch>` — the integration branch by name, never a shell variable; the one git read the barrier prompt allows beside its named subcommands; the highest index, never a count, so a cherry-pick or duplicate trailer never double-charges, and a reverted ace commit's trailer still counts). The Workflow seeds each task's `absorbRounds` from it (both id dialects match); an absent map, a missing entry, or a malformed value ⇒ `absorbRounds` 0 with a loud log naming the task. A Lead override rides `args.absorbCharges` on a relaunch and wins over the barrier read (logged) — read unconditionally, never gated on `args.recovery`. A relaunch may also seed `tasks[].pendingAbsorbs` (§Workflow per-phase args contract). Never a hold.

## `env-blocked` — the task outcome the evidence gate produces
A task reaches the refiner with exactly one terminal **outcome**. Two are produced by the worker itself (a `WorkerResult` with `status: "implemented"` or `"blocked"`, above). A third — **`env-blocked`** — is **not** a worker result: it is produced when the **per-task provision-run** returns an evidence-bearing `ok: false` (per the gate above), **before any worker is spawned**. The worktree never became gate-ready, so there is nothing for a worker to do. The escalation carries `{ taskId, failedCommand, exitCode, stderrTail, provisionSource }` from the real result fields.
- **The worker is NOT spawned.** The barrier runs each `run.provision` command in order after creating the worktree and before launching the worker; the first failure short-circuits to `env-blocked` and the worker launch is skipped entirely. This is distinct from a failed gate (broken code) — here the *environment* never came up.
- **No `WorkerResult` is produced for an `env-blocked` task** — there is no `branch`/`head_sha`/`tests`, because nothing was implemented. Do **not** add `env-blocked` to the `WorkerResult` schema above; it is its own task-outcome shape. (This corrects earlier "worker result schema" wording in the design spec, B.3.4/B.4 — `env-blocked` is a task outcome, not a worker result.)
- **Lead handling** (halt the task, escalate, **0 FIX rounds**, **keep** the worktree for inspection, siblings proceed) is specified in [SKILL.md](../SKILL.md). The red-team analogue of a provision failure is a probe `status: "warn"` (never a red verdict), not `env-blocked`.

> The *behavioral* assertion that the barrier emits this exact shape and does not spawn the worker is exercised in the refiner Provision-barrier test (`skills/war/assets/workflow-template.test.mjs`), not here — this section is the data contract.

## `env-died` — the post-spawn dispatch death (D21, #1411, #1481)
A dispatch that spawned and then died under the harness (API/quota/transport) is an environment event, never a content verdict. Read-only audit/probe deaths retain their site-specific soft or subset-abandon classifications. Pin rebases additionally have independent pre/post Git proof before transfer accounting. A mutating task/polish/terminal merge or land first receives bounded in-phase Git reconciliation by a fresh refiner; success requires matching Git evidence, and unmerged requires unchanged local and remote target refs plus matching source identity. Unresolved uncertainty holds before land. See [refiner-recovery.md](refiner-recovery.md#uncertain-merge-reconciliation) for the procedure and `MERGE_SNAPSHOT` / `PIN_GIT_PROOF` / `MERGE_CONFIRMATION` / `MERGE_RECONCILIATION` in `workflow-template.js` for the wire shapes. A proved-unmerged infrastructure death can retain `env-died` soft; it never acquires that classification solely because its response died. `env-died` remains in `SOFT_ENV_REASONS`, not `HARD_ESCALATION_REASONS`.

```jsonc
  audit_sha: "<sha reviewed — verdict is pinned to it>",
  verdict: "approve" | "request_changes" | "escalate",
  findings: [ { severity: "Critical"|"Major"|"Minor"|"Nit",
                title,
                file?,              // repo-relative path, omitted when the finding names no file (the executable AUDIT_VERDICT literal types `file` as a string and never lists it in the items `required` array).                 line?, rationale, suggested_fix?, plan_ref?,
```

- **`rationale` carries two closing conventions from corrective round 2** (ADR 0052, no schema change): on every blocking finding a roster seat writes `upstream link:` (one sentence: the link on the seat's own chain the new blocker descends from) and then `relation: <tag>` as the exact LAST line. The closed tag set is canonical in [backward-chain-audit.md](backward-chain-audit.md) `## The rules` and is never restated here (two guards bind the four surfaces: the skeleton guard `skills/war/assets/backward-chain.test.mjs` binds the audit rules block, the fixer file's Round 2 table and the examples bank's tag H2s (those between `## Entry shape` and `## Growth rules`), and a `workflow-template.test.mjs` fixture binds the engine's `relation:` regex in `workflow-template.js` to them; a fifth copy would owe a guard). The engine reads the tag by that regex and threads it in the history digest; the tag selects the fixer's first move and the examples section it reads. Round-1 findings carry neither line (a first audit has no fix to relate to, PIN-10). The three gate-audit-family seats never write them.
- **`severity` becomes schema-required** on finding items (`required: ['severity']` in the executable literal — previously finding items had **no** required array; this release introduces the requirement, ADR 0013 resolution 3). Schema-layer retry corrects a sloppy seat; persistent failure falls into the existing dropped-seat → audit-blocked lane.
- **`escalate_reason` is conditionally required** (*amendment 2026-08-15, #1410*): the executable `AUDIT_VERDICT` literal carries a JSON-Schema `if`/`then` conditional — `verdict: "escalate"` ⇒ a non-empty (`minLength: 1`) `escalate_reason`. Enforcement arm recorded by the Task 2.1 worker probe (code-read of the running `agent({schema})` layer, harness v2.1.228): the layer Ajv-compiles the full schema and re-prompts a non-conforming seat (bounded conform-or-retry); its strict-schema deriver has no `if`/`then` and already fell back to non-strict on this schema, so the retry loop is the enforcement point — a reason-less `escalate` is re-prompted, and a persistently non-conforming seat falls into the existing dropped-seat → audit-blocked lane (`verdict = 'audit-blocked'` on `seats.length < expected` — the same lane the `severity` bullet above names), so there is no NEW hold path: a reason-less `escalate` already held as `held:escalation`; the outcome class is unchanged (#1410).
- **`widen` is optional and only meaningful on a lone seat** (D4). When a 1-seat roster returns a Critical or low-confidence verdict, `resolveWidenSource` ([`../assets/war-config.mjs`](../assets/war-config.mjs)) reads `widen`: a **valid** nomination — a non-empty array of distinct, non-empty lens names, **none reserved** (`execution-evidence`/`pin-validity`) — widens toward those lenses at `deep`; absent/invalid → the default roster's lenses (the byte-identical default-roster-union fallback). Validity is strict whole-field (any bad entry rejects the whole nomination). It is **never reserved-selectable** and never honored on a multi-seat roster (a roster the human approved is not second-guessed).
- **`barrier` provenance rides every filed row** (in-band-absorb-default D4/D13): a seat-filed `follow-up` keeps its `barrier` tag on the `minorsFiled` row (the file-followups prompt renders it as `filed-by: seat-filed (barrier: <tag>)`); a row `demote()` filed carries `engineFiled: true` plus `demoteReason` (its `DEMOTE_REASONS`-prefixed reason — canonical in `land-decision.mjs`, inline mirror in `workflow-template.js`), and the intake floor skips `engineFiled` rows (an engine demotion is never rerouted); a seat row filed with no intake floor run carries `floorSkipped: true` (rendered `demote:floor-skipped`) — the probe failed, or the row was raised at the escalation arm, the sweep, or the terminal pass, where no probe applies (#2051). Canonical: `demote` / `intakeFloor` / `filedByOf` in `workflow-template.js`.
- **`scopeBreach` is optional and only meaningful on a delta-scaled re-audit seat** (PIN-18, #1913). The seat re-runs `git diff --name-only <sha>^ <sha>` itself; any changed file outside the ace worker's claimed `ace_diff_files` set means `scopeBreach: true` and the file named in a finding — the transfer is refused and the full panel re-runs. It is never a finding severity and never a status; canonical shape: the `AUDIT_VERDICT` literal in `workflow-template.js`.
- **`plan_ref` doubles as the End-state key** on gate-audit findings: an End-state finding carries the claimed condition text **verbatim** in `plan_ref` — the same verbatim-condition key the `endStateAttestations` rows and the handoff `endState` block use.
- **`endStateAttestations` is the positive End-state channel** (D8, the 2026-08-05 precision-chain plan; gate-audit-family seats only — per-task (post-merge), integrated-tip, end-state-only; produced by its Task 3.2, landed 0.17.0). Each gate-audit-family seat returns **one row per claimed condition**: `condition` is the claimed condition text **verbatim** (the `plan_ref` key), `status` ∈ `met | unmet | unverified`, `evidence` cites what the seat actually read — the teed per-condition artifact for a `check:`-tagged condition, the named observable for a judged one — never a bare verdict. An artifact that is present, readable, and correctly tip-stamped but **red for environmental reasons** — a setup/collection/import failure (`ModuleNotFoundError`, pytest setup `ERROR`, usage/collection exit codes) rather than the condition evaluating false — attests `unverified`, never `unmet`: a met condition is never attested `unmet` for want of environment prep (#1395; the land-barrier endstate-check dispatch applies the phase's `run.provision` steps in `_refinery` before any `check:` command, fail-open — a provision red is recorded into the artifact preamble and the checks still run). Two record-only artifact states the same dispatch stamps attest the same way: an `intake_lint:`-stamped artifact (the check literal failed the intake lint, so the row was never executed) and a `cmd_bytes_mismatch:`-stamped artifact (the written `.cmd` failed the byte-for-byte verify, so the row was not executed as declared) attest `unverified`, never `unmet` (#1781; the seat surfaces direct the same mapping — the `endStateBlock` ATTESTATION clause and the auditor card's execution rung 1). Ordinary audit-seat results are unchanged and never carry the field. Findings stay **defect-only** (findings carry defects; attestation rides `endStateAttestations` — two separate contracts): attestation rides this channel, never a finding. The handoff maps a condition with **no attestation row from any seat** to `unverified`, never `met`.

- **`integration_sha`** — the post-rebase integration tip the gate ran at; the post-merge gate-audit pass reads it as gate-HEAD provenance to confirm the executed `gate_output` corresponds to the integration tip (it does not add a field; `integration_sha?` already exists).

Every normal merge/land reply receives a separate read-only Git confirmation before routing:
`mode` and `status` alone do not establish success or absence. Success needs a usable reported
SHA resolved independently to the actual full local/origin target identity and the task
fast-forward/patch or exact land-parent proof. A reported failure needs unchanged target refs and matching source identity (task diff or exact land source).
Missing, contradictory or unavailable proof enters bounded refiner recovery; only verified
results can reach task completion, approval accounting or Wrap-up. The shared runtime
`mergeGitMatches` predicate and `MERGE_CONFIRMATION` / `MERGE_RECONCILIATION` declarations are the
wire-shape authority; see [refiner-recovery.md](refiner-recovery.md#uncertain-merge-reconciliation).

The base-run evidence rides `gate_output` **uncurated** (judgment, not parsing). `gate_failing_ids` (the classified failing-identifier set) and `gate_base_sha` (the classification base sha) are populated on a `baseline` result — they are the Workflow's dedup key, the `source: 'auto'` backstop `check` string, and the baseline-proceed prompt's named identifiers.

## PinTransfer — `war-refiner` (merge slot, before merge-task)
```jsonc
{ status: "transferred" | "mismatch" | "already_upstream" | "empty-unmatched" | "conflict" | "error",
  rebased_tip?,                       // the actual rebased task branch tip (equal to integration only when already_upstream)
  dispatch_base?,                     // the pre-rebase BASE (`git merge-base <integrationBranch> <taskBranch>`) the probe measured PRE from; returned on every result that carries rebased_tip. OPTIONAL on the probe wire: independently computed Git proof supplies it for transferred/mismatch; already_upstream requires the reported base to resolve to the actual pre-rebase base
  pre_rebase_patch_id?,               // `git patch-id --stable` of the task's own diff, dispatchBase..tip, measured BEFORE the rebase (empty when the diff is empty — patch-id prints nothing)
  post_rebase_patch_id?,              // the same measure after the rebase, integrationTip..tip
  already_upstream_commits?: ["sha"], // the TASK commit shas `git cherry` matched upstream (git cherry names task commits, never upstream equivalents)
  conflict_files?: ["path"],          // on status "conflict"
  detail? }                           // free text: the failing leg on "empty-unmatched", the error on "error"
```
The probe rebases and measures; it never merges, never pushes the integration branch, never runs the gate or a floor. Separate read-only snapshots and `PIN_GIT_PROOF` verify the actual approved content, target refs, patch IDs, resolved pins and cherry evidence before any receipt or completion; see [refiner-recovery.md](refiner-recovery.md#uncertain-merge-reconciliation). Missing/error/unknown replies cannot hide changed content. Git contexts explicitly name the integration target and its seed: the ordinary working branch or the submodule targetBase. Equal cardinality, distinct resolved claims and coverage of each claim require exact cherry-set equality. Deliberately its **own** schema, not a widening of `MergeResult`: **no** `MergeResult` status value, `HARD_ESCALATION_REASONS` member, or `KNOWN_LAND_DECISIONS` member is added or changed (`land-decision.mjs` untouched, ADR 0005), so no pin-transfer outcome can ride an in-band field on a hard-escalating wire status.

- **`transferred`** — `pre_rebase_patch_id` is non-empty and equals `post_rebase_patch_id`: independent exact content identity must also match before the panel's audit pin transfers to `rebased_tip` and no panel re-convenes in the lock.
- **`mismatch`** — the ids differ: the Workflow re-audits `rebased_tip` with the **full panel, in the lock**, before the merge — the pre-transfer behaviour, for that one task only. A non-approving re-audit escalates.
- **`already_upstream`** — the post-rebase task diff is empty, the task had at least one commit, every non-merge commit listed by Git cherry-matched upstream, and the pre-rebase patch-id was non-empty. The engine also requires the actual final tree to equal the approved tree before recording `merged` at `rebased_tip` with the matched commits named and no panel or content merge. Otherwise the full content re-audit compares the original approved task and changes since approval; unanimous fresh approval plus unchanged published Git refs records a `mismatch` receipt and completion without an empty merge. See the canonical [proof procedure](refiner-recovery.md#uncertain-merge-reconciliation). The consumer **refuses** an `already_upstream` whose fields carry the **contradiction signature** — `rebased_tip` equal to `dispatch_base`, a non-empty `post_rebase_patch_id`, or an empty `already_upstream_commits` — and routes by patch-ids instead (equal non-empty ids → `transferred`, anything else → the `mismatch` re-audit; D4, PIN-8, #1973). Guarded by the `pin-transfer: #1973 verbatim replay merges the task` and `pin-transfer: already_upstream contradiction legs` fixtures in `workflow-template.test.mjs`.
- **`empty-unmatched`** — an empty post-rebase diff that fails any of those legs (zero task commits, an unmatched patch, or an empty pre-rebase patch-id). Fails **closed** to a hard escalation (reason `escalate`): a zero-commit branch is vacuously an ancestor, and recording it merged is the silent-success failure #1895 named.
- **`conflict`** — the rebase conflicted; escalates on the existing hard reason `conflict`. **`error`** — unclassifiable git/env problem; the ordinary merge fallback requires independent proof of unchanged approved content or an equal patch. A changed patch gets the full re-audit; missing proof holds.

## GateCheck — `war-refiner` (at an ace tip, read-only)
```jsonc
{ gate_green: true, head_sha, gate_output? }   // green arm — head_sha REQUIRED at the validator (#1951)
{ gate_green: false, head_sha?, gate_output? } // red arm — sha-free
```

The task gate (and the task's `Done when:` command) run at an ace-family commit **before** its re-audit, so no approval — re-run or transferred — is ever accounted at a SHA the gate never passed. ## Gate rule (applied over AuditVerdicts)
- any open **Critical/Major** (any seat) → **blocks** → batched `FIX_NEEDED`
- any **escalate** → **halts** to the Lead
- **all `approve`**, no open Critical/Major, **same `audit_sha`** → merge-eligible (**convergent unanimity** — if HEAD moves, every seat re-confirms against the new SHA)
- split (mixed approve / request_changes) → **one rebuttal round** (each seat re-judges seeing peers' findings) → unanimous-approve | agreed-block (FIX_NEEDED) | a surviving blocker with a `suggested_fix` (FIX_NEEDED — rebuttal first, then fix round when all surviving blockers have a suggested_fix) | a fix-less survivor (escalate, `escalate_reason` read into `escalated[]`) | a mandate conflict on one locus (an operator `ask` while held, never approval)

- **`merge_sha` is advisory** — authoritative only when reachable on the branch (the reconciliation pre-flight's invariant; git is monotonic, so a recorded `merge_sha` is real iff its commit is reachable). The ledger is a lagging view; git branch state is the authority ([ADR-0008](../../../docs/adr/0008-git-is-the-resume-source-of-truth.md)).
- **`pr_number` / `pr_remote` are advisory** — recorded when the Workflow enters `held:submodule-pr`; read by the Resume procedure to confirm the PR state via `gh pr view`. Absent on superproject phases and on submodule 2A (WAR-owned) phases that land without a PR.
- **`submodule_merge_sha` is advisory, authoritative-when-reachable** — same rule as `merge_sha`: the gitlink pin is authoritative only when reachable on the submodule remote (`git -C <submodule-checkout> fetch && git cat-file -e <submodule_merge_sha>`). A SHA not reachable on the submodule remote → treat as class A (ledger-ahead for the pin; clear the pin, surface to the user before re-landing). Written on resume from `mergeCommit.oid` (2B) or from the CAS push result (2A).

## Run manifest — `.claude/war/runs/<runId>.json` (telemetry, not resume state)
Fail-open per-run **telemetry** the `/war` Lead accumulates at phase boundaries and `/war-review` consumes. **Distinct from the `ledger.json` above:** the ledger is run **state** — the git-authoritative correctness record ([ADR-0008](../../../docs/adr/0008-git-is-the-resume-source-of-truth.md)) at `.claude/teams/<run-id>/`; the manifest is a cost/effort record at `.claude/war/runs/` that **no code reads back**. It is Lead-side bookkeeping in `/war` prose, not an engine structure.

- **Location:** `.claude/war/runs/<runId>.json` under the **main checkout** (anchored via `git rev-parse --path-format=absolute --git-common-dir`, never the invoking worktree's `.claude/`). `runId` follows [launch-identity.md](launch-identity.md) (`new-run-id.mjs`, persisted UUID). Untracked — rides the existing `.claude/` exclude the provisioning `ensure-exclude` step maintains (no `.gitignore` change). A same-run resume updates the file in place (latest-wins per `runId`).

```jsonc

  configProfile: "balanced|thorough|economy|<custom>",  // MUST
  startedAt: "<ISO 8601>",                              // MUST — run launch; a real clock read captured at the stamped boundary (e.g. `date -u +%Y-%m-%dT%H:%M:%SZ` at stamp time), never a placeholder or copied literal
  endedAt: "<ISO 8601> | null",                         // MUST — null until the run ends; then a fresh clock read at run end

    { id: "phase-1",
      startedAt: "<ISO 8601>", endedAt: "<ISO 8601> | null",   // MUST — per-phase boundaries, each a real clock read captured at its stamped boundary, never a placeholder or copied literal

```

- **MUST-carry** (field names are the spec's contract; nesting may be refined, the list is binding) — per-phase `transcriptDir`, `workflowRunId`, ISO-8601 timestamps (top-level run + per-phase), dispatch counts by role, task terminal statuses, `sweepExcludeCount`, `finalPhase`, and the `envelope` aggregates (binding-to-attempt, null-tolerated — the `workflowRunId` posture); top-level `runId`, `planPath`, `configProfile`, and run `startedAt`/`endedAt`. These are what `/war-review` consumes (`finalPhase` excepted — manifest-only today, per the next bullet); anything the Lead cannot source is `null`/omitted and the review renders `n/a` (**never** fabricated).
- **`sweepExcludeCount` / `finalPhase`** (PIN-8) — stamped at phase launch, never re-derived from the engine log: the count is the length of the `args.sweepExclude` array the Lead threaded (`null` when it threaded none), and `finalPhase` is the `args.finalPhase` value threaded (`null` when absent). The Lead procedure is [sweep-exclusion.md](sweep-exclusion.md). `finalPhase` is manifest-only today — `/war-review` renders `sweepExcludeCount` alone.
- **`tasks` vs `land`** — `tasks` maps each task id to its **task** terminal status (the `ledger.json` task-status enum above: `merged`|`escalated`|`blocked`, or `env-blocked`); `land` is the phase `landDecision` (`landed`|`held:*`, the Workflow per-phase return enum below). Both are copied from the Workflow per-phase return / handoff, not re-derived.
- **Relaunch (`attempts[]`)** — a relaunched phase (a `resumeFromRunId` retry or a Recovery relaunch) overwrites `workflowRunId` + `transcriptDir` **together**, archives the died attempt under `attempts[]`, and sums dispatch counts across attempts. The `attempts[]` shape lives **only** in [run-manifest.md](run-manifest.md) § Relaunch (de-mirrored — this section does not restate it).
- **The review saves a sibling** — `/war-review` renders the manifest + its transcripts into `.claude/war/runs/<runId>-review.md` beside the manifest (always written; a `/war-review` output, not a `/war` write).
- **Fail-open, never resume input** — every manifest write is best-effort: a failed write logs one line and the run proceeds unaffected. The manifest is telemetry only; the resume source-of-truth ordering (git > issues > ledger, [ADR-0008](../../../docs/adr/0008-git-is-the-resume-source-of-truth.md)) is untouched.

## GitHub conventions
- **Epic issue per phase**; **sub-issue per task** (GitHub sub-issues).
- Labels: `phase:<N>`, `status:todo|working|audited|merged|escalated|blocked`, `audit:<seatCount>`.
- **Minor/Nit** findings route by **disposition** (ADR 0013): `follow-up` → a new issue labeled `war-followup`, linked to the phase epic (an affirmative act — the auditor stated why it is not absorbable); `note` → phase report + servitor feed, never an issue; `absorb` → fixed in-phase by the per-task ace (under `run.ace`) or by the phase-close sweep when `phaseClose:true` (the sweep and the terminal pass run with `run.ace` off too; a `RELEASE_SLOT_FILES` absorb demotes at birth with `demote:release-slot` and never reaches the sweep — PIN-11), and recorded on the Workflow's `aced` list (commit-cited, not a GitHub issue); `ask` (#1550, ADR 0013 amendment 2026-08-25) → a decision-shaped Minor/Nit only the operator can rule (question+fork mandatory), parked on the run's `asks[]` and ruled at the Checkpoint strike-list gate — **never filed unruled**; a ruled ask whose fix is fully specified **executes in-run** (next-phase decompose injection, or the final phase's polish-style dispatch — ADR 0013 amendment 2026-08-27), and files **Lead-side** with filing parity (an `## Evidence artifacts` section + dedup against engine-filed rows) **only** on cannot-execute or execution-failure, the ruling recorded in the issue either way. An ace re-audit regression enters the bounded **ace bisection** ladder (canonical: `aceBisect` in `../assets/workflow-template.js`) — salvaged subsets record on `aced` at their subset shas. A regressed absorb (the fix itself broke a re-audit) **demotes one step** with a `DEMOTE_REASONS` prefix (logged — per subset under bisection); a failed ATTEMPT (an untouched file, a dead ace worker, a red gate at the ace tip) and an ace-off run route the row to the phase-close sweep instead (in-band-absorb-default D13/D14), while `demote()` **refuses an ask** unconditionally — log() + re-route onto `asks[]`, never `minorsFiled`/`notes` — so in-phase `war-followup` filing consumes `follow-up`-routed findings (including demotions), and nothing drops silently on any exit path. Legacy `autoFixable:true` reads as `disposition:'absorb'` for one release (deprecated).
- Phase reports + escalations → **comments on the phase epic issue** (durable, human-visible).

## Filing result — the `file-followups` dispatch (Land)
Canonical shape: **`FOLLOWUP_FILING_RESULT`** in `../assets/workflow-template.js` (the schema and its field comments are the source of truth — this section summarizes routing, not fields). ADVISORY, all fields optional (fail-open): a dead/non-conforming return leaves `handoff.followUps[]` issues null; the Checkpoint filing floor (SKILL.md § Checkpoint) is the catch.
- **Consolidation precedes filing — on the filing-eligible land decisions only.** The collapse and the dispatch it feeds run **iff** the land decision is `landed` / `held:escalation` (the handoff-emitting pair, #1597) / `held:land-failed` (a failed land never silently un-runs the filing — no handoff emits there, so the stamped issue numbers ride the top-level return's `minorsFiled`) and `minorsFiled` is non-empty; on every remaining hold (`held:nothing-merged`, `held:phase-incomplete`, `held:workflow-error`, `held:submodule-pr`) the rows are neither collapsed nor filed — they return uncollapsed and unstamped (no `.issue`), while engine stamps such as `drainCause` still ride them. The collapse mechanics — key, fallback, in-place splice — are canonical in the FOLLOW-UP CONSOLIDATION block (`FOLLOWUP_LINE_WINDOW`) in [`../assets/workflow-template.js`](../assets/workflow-template.js), never here; in summary, duplicate rows collapse deterministically and a collapsed row carries a **`seats[]`** corroboration list. Consolidation and the dispatch consume `minorsFiled` **only** — parked `asks[]` records are structurally excluded from both (an unruled ask is never filed; #1550). `filed[]` row ordinals (`n`, 1-based) index these **post-collapse** rows, and the Workflow stamps `minorsFiled[n-1].issue` from each in-range row.
- **`clusters[]`** is the agent's own clustering manifest over the post-collapse ordinals (`{ ordinals, issue }`). The engine asserts: every ordinal in exactly one cluster (clustering only merges the engine's collapsed rows, never splits one) and distinct issues filed ≤ post-collapse rows; a violation gets ONE log line — fail-open, never a hold.
- **Corroboration comments.** An open `war-followup` match receives this batch's finding as a comment on the existing issue, **never a new issue**; several rows may share one issue number (ordinal→issue stamping unchanged).

## ScoutResult — `war-setup-scout` (once, before provisioning)
The read-only, Explore-class setup-scout (`agents/war-setup-scout.md`) reads the **target repo's own** setup signals and derives an ordered provisioning command list. It returns **only**:
```jsonc
{ provision: ["<shell cmd>", ...],   // ordered; submodule-init before install; [] is valid
  source: "explicit" | "manifest" | "ci" | "onboarding" | "structural",  // the highest-authority tier that yielded signal
  rationale: "which signals were read and why this list, in this order" }
```
- **Authority (descending):** `explicit` (a non-empty `run.provision` honored verbatim, no scouting) → `manifest` (a committed `.war-provision.json`, tier 1 — above CI, below explicit) → `ci` (`.github/workflows/*.yml`) → `onboarding` (`.devcontainer`, a `Makefile`/`Justfile` `setup` target, `package.json scripts.{setup,bootstrap,prepare}`, CONTRIBUTING/README setup sections) → `structural` (the tiny floor). The scout stops at the first tier that produces a list.
- **Scout subset vs. config enum.** The scout **emits** `{ explicit, manifest, ci, onboarding, structural }`. The full `run.provisionSource` config enum is wider: `explicit | manifest | ci | onboarding | structural | none` ([`../assets/war-config.mjs`](../assets/war-config.mjs) `PROVISION_SOURCES`). `none` is the unscouted/empty default and is never emitted by the scout.
- **No ecosystem table:** every command is traceable to a signal actually read in the repo, or to the deterministic structural floor — `structuralFallback` in [`../../_shared/provision.mjs`](../../_shared/provision.mjs) (submodule-init + a single known-lockfile install only). The scout never synthesizes an install from a guessed language/framework.
- **Guarded downstream:** `provision` must pass `validateProvision` (array of non-empty trimmed strings) before it is pinned, and the operator reviews `{ provision, source, rationale }` during war-room Setup. There is no automated test for the scout; its golden-check is the checked-in fixture + [`../../_shared/fixtures/provision/EXPECTED.md`](../../_shared/fixtures/provision/EXPECTED.md) (deterministic coverage of the floor lives in `provision.test.mjs`).

This result is the *derivation* output; pinning it into `run.provision` (and the every-time execution that follows) is governed by the §Run config below.

### Provisioning manifest (.war-provision.json)

A committed JSON file at the repo root that declares an ordered provisioning list. The scout reads it as **authority tier 1 — above CI, below explicit operator `run.provision`** (closes [#51](https://github.com/Ljferrer/WorkAuditRefine/issues/51)).

**JSON schema:**
```jsonc
{ "provision": string[],   // required; ordered; [] is valid ("no steps")
  "rationale"?: string }   // optional human note
```
- `"provision"` is required and must be a `string[]` passing `validateProvision` (non-empty trimmed strings).
- `"rationale"` is optional.
- No other top-level keys are permitted (source assigned-not-declared rule — see below).

**source assigned-not-declared:** The manifest carries **no `source` field**. The reader stamps `source: "manifest"` after a successful read. A manifest that includes its own `source` key is **rejected** (unknown-key error) — a repo cannot claim a higher authority tier by self-declaration.

**fail-loud-on-broken contract:** A present-but-broken manifest **stops with errors** — it does not silently fall through to CI. The reader (`readManifest` in `skills/_shared/provision.mjs`) returns `{ found: true, ok: false, errors: [...] }` for any of:
- Unknown top-level keys (including a self-declared `source`)
- Malformed / non-JSON content
- Non-object JSON (e.g. `null`, `[]`, `"x"`, `42`) — `JSON.parse` succeeds on these, so an explicit object guard is required before key inspection
- A `provision` entry that fails `validateProvision` (blank / whitespace-only string)

On a successful read: `{ found: true, ok: true, provision: [...], rationale?: "..." }`. Absent file: `{ found: false }`.

**Absence is safe:** no `.war-provision.json` → the scout continues to CI exactly as before. This is purely additive.

## Workflow per-phase args contract
`args` may be passed as a **plain object or a JSON string**; the template auto-parses a string so the Lead need not manually inline structured data.

Optional `agentPrefix` (default `"work-audit-refine:"`) — the template auto-namespaces every `agentType` seat under this prefix via `const NS = args.agentPrefix ?? 'work-audit-refine:'`. Pass a different string to override; the Lead no longer needs manual namespacing workarounds.

Optional `ghUser` (string, default `''`) — the expected `gh` account for the Workflow's own gh-write dispatch (the `file-followups` filing), threaded by the Lead from `overrides.ghUser`; the dispatched prompt preflights it via `gh-preflight.sh` (an empty string is the preflight's documented no-op). A non-string value falls back to `''`.

Optional `intent` (string|null, ADR 0013) — the plan's `## Commander's Intent` or `## AI-Commander's Intent` section (either heading), extracted **verbatim** by the Lead (never Lead-invented — `/war-machine --afk` is the sole authoring surface allowed to author intent, ADR 0014; neither section present → `null`). When present it is threaded into the worker, auditor, ace/sweep, gate-audit, and servitor prompts as the ceiling over the plan-slice floor. `null`/absent ⇒ every prompt is **byte-identical** to an intent-less run — literal behavior. Companion field `phase.endState` carries the intent's End-state conditions **this phase claims** (Lead-mapped) as rows `{ condition, tag, check }` — `condition` the verbatim condition text (ADR 0013/0014 extraction unchanged), `tag` the condition's parsed D5 End-state tag (ADR 0044's End-state tag law) (`"check:" | "gate:" | "HARD at audit_sha" | "backstop:"`, or `null` when untagged), `check` the executable command of a `check:`-tagged condition (string; `null` on every other row). **Bare-string normalization:** a legacy bare-string entry normalizes to `{ condition: <the string>, tag: null, check: null }` — the judgment path — so consumers never see a raw string (widened from `string[]` by the 2026-08-05 precision-chain plan; parsed by its Task 3.1 and executed at the land-barrier endstate-check dispatch by its Task 3.2, landed 0.17.0). The gate-audit pass checks them at the confirmed tip (conditions owned by a later phase — or by a deps-chained sibling task of the same phase not yet landed at the audit's scope — are out-of-scope there, never a hold).

Optional `memory` (spec §4.5) — the Lead's per-phase prior-lesson prefetch, shaped `{ byTask: { <task-id>: { worker, seats: { <lens>: block } } }, servitor }`, where each `block` is the `war-memory query` CLI's ready-to-inject text. Threaded like `intent`: the template concatenates a `memoryClause` at the worker, auditor, fix-worker, add-test, and servitor spawn sites (ace / gate-audit / polish-sweep get none). An empty/absent map ⇒ every prompt is **byte-identical** to a memory-less run. Retrieval fails open — a missing `memory` is never an error.

Optional `adjudications` (array|null) — preformatted strings or `{ adjudicated|value, supersedes }` objects (row shapes unchanged by this widening). **Three producers** feed the set: the plan's red-team report `## Adjudications` block (`docs/red-team/<plan-slug>.md`), the Lead's own decompose-gate / escalation-time scope adjudications, and the Checkpoint ask rulings (#1550 — each ruled ask minted as an adjudication row at the strike-list gate), assembled and recorded per [SKILL.md](../SKILL.md). Threaded like `intent`: the template concatenates an `adjudicationClause` at the roster-seat `auditPrompt` and the three gate-audit-family seats (per-task (post-merge), integrated-tip, end-state-only). Empty/absent ⇒ every prompt is **byte-identical** to an adjudication-less run.

Optional `ruledAsks` (array|null, D15(b)/PIN-17, #1879) — interactively-ruled asks with fully-specified fixes, threaded by the Lead for the phase-close polish-style execution vehicle. Record shape `{ task?, file?, line?, suggested_fix, ruling, planSlug, phase, findingTitle }` — `suggested_fix` and `ruling` required, plus the three **REQUIRED** provenance coordinates `planSlug` / `phase` / `findingTitle` (#1879 RULING 2). The intake conjuncts and drop-and-log refusal semantics are canonical in `ruledAskIntakeReject` (and the floor's per-row intent-bearing text in `ruledAskRowText`) in [`../assets/workflow-template.js`](../assets/workflow-template.js); the arg also joins the args-provenance floor below (a foreign record can refuse the launch at entry). Empty/absent ⇒ byte-identical to a ruled-ask-less run.

**Args provenance floor (#1413; recalibrated per D6 of the 2026-08-25 engine-reliability-and-filing-fidelity plan):** entry validation refuses — before any agent spawns, `held:workflow-error` — an assembled `intent`, `backstops`, `adjudications`, `ruledAsks`, or `seededPhaseClose` arg the floor classifies as a cross-plan leak (a `ruledAsks` or `seededPhaseClose` row's provenance stamp is read as the record's `planSlug` **field** — anchored on the run `planSlug`, falling back to `plan.file`'s basename — never as prose). *This row is an informal summary — the refusal contract is canonical in the template's `ownTokens`/`foreignIds` region ([`../assets/workflow-template.js`](../assets/workflow-template.js)); consult that region for the exact token derivation, stoplist membership, and exemption predicates.* In outline: a foreign `docs/plans/<slug>.md` identifier differing from `plan.file` refuses; the own-token check refuses an arg carrying **none** of the run's own plan-slug tokens, scanning **intent-bearing arg text only** (never a whole-surface stringify-substring match) with **word-boundary** matching behind a generic-token stoplist; and `source:'auto'` rows and Lead-stamped `planFile` provenance rows are **exempt** from the own-token requirement only; a predecessor citation never reaches the foreign-id match (an object row's `supersedes` field never enters the scanned text, and a string row's citation segment is stripped before the foreign-id match, #1751). **Foreign-id detection is not part of the exemption** (D10 of the 2026-09-06 engine-and-audit-verdict-integrity plan, #1749): the foreign-plan-id scan (`foreignIds`) runs over every row's intent-bearing text, exempt rows included (the same every-row scope `evidenceText` gives the own-token search — #1666's exempt-row satisfaction stands, never narrowed), so a foreign args blob naming a foreign plan id is refused even when its rows all carry `source:'auto'`. **Adjudication rows are never token-doped** (#1480): an `adjudications` surface whose every row is a canonical `{ adjudicated|value, supersedes }` object or the adjRow string render `<value> (supersedes plan literal: <x>)` passes the own-token floor without a token — a value row is not intent-bearing text — so those two Adjudications shapes launch as written (a preformatted string in any other shape is own-token-scanned); a preformatted string row strips its `supersedes … docs/plans/<x>.md` segment before the foreign-id match (#1751). An empty `ownTokens` with a present `plan.file` falls back to the plan basename as the single anchor and logs the fallback (#1767). Defined here, produced by Task 6.1 of that plan — the exact predicates are the template's `rowText` / `isValueRow` / `ownTokens` / `foreignIds` / `evidenceText` / `idText` helpers, never this row (`isValueRow` is the value-row predicate, and it admits only the `adjudicated` / `value` / `supersedes` / `planFile` / `source` keys on an object row and requires the value field to be one whitespace-free token of at most 64 characters, so an adjudication row carrying any other key, or a prose ruling in the canonical shape, is own-token-scanned; `idText` is the citation-stripped every-row text the foreign-id match reads). The own-token floor applies only when its arg yields scannable non-exempt intent-bearing text (an intent-less launch stays legal, and so does a present, non-empty arg whose rows carry no scannable text); the foreign-id scan applies whenever any row yields text and `plan.file` is present.

Optional `absorbCharges` (object|absent, absorb-budget D5) — `{ <task>: n }`, the Lead's relaunch override of the barrier's `Ace-Charge` read (see the ENV_OUTCOME `absorbCharges` bullet); read unconditionally (no `args.recovery` gate) and wins over the barrier map, logged. A non-object value is logged and ignored.

Entry-validated at intake (a non-array, a non-object entry, a missing `slug`, or a non-string-array `files` refuses the launch, naming the entry index and field — never coerced). Absent ⇒ one log line ("no campaign contention set threaded"); the in-phase and release-slot arms still run.

Optional `seededPhaseClose` (array|absent, in-band-absorb-default D3b/PIN-5) — the Lead's carry of the prior phase return's top-level `carriedPhaseClose` from every phase return, landed or held, threaded **verbatim** per [resume-and-recovery.md](resume-and-recovery.md): an array of finding rows `{ severity, title, file?, rationale?, suggested_fix?, task?, planSlug?, carriedFrom? }`. Entry-validated at intake (a non-array, a non-object entry, a missing `title`, a `severity` outside `Minor`/`Nit` (every carry producer emits absorbs, never a blocker), or a non-string `file` refuses the launch naming the entry index and field — never coerced) and it **joins the args-provenance floor** above under the `ruledAsks` discipline: the row's `planSlug` field is the provenance coordinate (a foreign slug refuses at entry; the run's own slug — which the emitting engine stamps on every carried row — exempts it; a stamp-less row's `title`/`rationale`/`suggested_fix` text must carry an own-plan token). Absent ⇒ byte-identical to a seed-less run.

Optional `finalPhase` (boolean|absent, in-band-absorb-default D3a) — the terminal pass's finality signal, threaded by the Lead from the plan's phase count at **every** launch. `false` ⇒ a terminal-born absorb (raised by the terminal re-audit seat), a regressed or unmerged terminal commit's rows, and a discarded sweep's absorbs ride `carriedPhaseClose` for the next phase; `true` ⇒ they demote to `follow-up` (`demote:terminal-pass` "raised on the terminal pass" / `demote:absorb-regressed` / `demote:sweep-discarded`). **Absent reads as final** (a missed thread files a visible issue instead of carrying into nothing). Optional `tasks[].pendingAbsorbs?` (array|absent, absorb-budget D5) — **relaunch-seed only**: `[finding rows]` (the AuditVerdict finding shape, `absorb` disposition) that a blocker-held batch ace held on `r.task.pendingAbsorbs` at a prior launch. Absent ⇒ nothing folds. The in-run hold never reaches this fold — `aceStage` runs once per task. A seeded row on a task that never runs a wave (barrier pre-merged, env-blocked, dep-blocked) gets the same judgment in the held-absorb drain, then — fileless ⇒ `demote:fileless` (severity default), a content-key duplicate within the batch ⇒ dropped, logged, otherwise — the sweep (merged) or `demote:absorb-blocked` (never merged). Auditors receive the **absolute `task.worktree` path** so they can `Read` candidate files directly in the task's isolated checkout rather than the main repo tree.

### Provisioning args (refiner-owned worktree lifecycle)
The refiner's **Provision** barrier ([ADR 0001](../../../docs/adr/0001-explicitly-managed-worktrees.md)) and the per-task branch/worktree derivation read these fields off `args`:

| field | meaning |
|---|---|
| `planSlug` | plan-slug for the **plan-namespaced** branch names ([ADR 0003](../../../docs/adr/0003-plan-namespaced-branches.md)). The template derives each task's branch as `war/<planSlug>/p<phase>-<task>`. |
| `runId` | run id segment in the worktree **path** (`<worktreeRoot>/<runId>/p<phase>-<task>` — phase-scoped, mirroring the branch shape); keeps concurrent runs' directories collision-free even when branch names share a slug, and normal phase progression never collides on a stale sibling worktree. | `worktreeRoot` | absolute dir that holds the per-run worktrees (e.g. `<repo>/.claude/worktrees`). |

| `ownedFile` | path to the run's owned-refs ledger, threaded to `ensure-integration --owned-file`; a `integration/<slug>/phase-N` that exists but is **not** in this ledger is a foreign collision → the script exits non-zero (fail-loud), distinguishing a resume from a cross-plan clash. |
| `recovery` | (optional; **partial-phase recovery**, spec §4.2/§4.4) `{ sanctioned: true, reclaimStaleRemote?: boolean }`. `runDir` (= `.claude/teams/<runId>`) is the run-scope for `provision-worktrees.sh` teardown.

- **`escalated[].defectClass`** — (optional metadata, spec §4.3; ADR 0005) `'plan'` iff the worker-authored `blocked_reason` was prefixed with the `PLAN-DEFECT:` sentinel (a shared JS constant; strict, case-sensitive `startsWith` at position 0 — no trim, no case folding; the sentinel is **left inside** `blocked_reason` as evidence, never stripped). **Absent** otherwise — never `'implementation'` by default, so prior-run escalation records stay shape-compatible. It is **orthogonal to `reason`**: it never enters `decideLand`, `HARD_ESCALATION_REASONS`, or `KNOWN_LAND_DECISIONS` (`land-decision.mjs` untouched). Tagged at every escalation site carrying worker-authored blocked text (the wave-collector push + the floor sub-loop's blocked-fix-worker push); it rides the machine-readable return into the Lead's adjudication (`defectClass: 'plan'` → a `/red-team` plan amendment, not worker fix-rounds).

`handoff` is emitted on `landed` **and** `held:escalation` (degraded: `polish:'skipped'`, End-state statuses as known — an escalated phase still hands off; the next decompose needs the debt map most exactly then). It is **omitted** on `held:workflow-error` (infra death — the ledger + issues are the record; there is no trustworthy return to render) and on the other holds (nothing landed to hand off). The Lead writes it to the ledger's phase-level `handoff` field.
When `landDecision` is a `held:*` value the land was **not** performed in-flow; the Lead lands manually and then runs `war-servitor` (see SKILL.md). The full `landDecision` enum:
- **`landed`** — the phase merged and pushed cleanly in-flow.
- **`held:escalation`** — a hard escalation (Critical/Major, unresolvable conflict, plan contradiction) halted the in-flow land; the Lead resolves and lands manually.
- **`held:nothing-merged`** — no task merged cleanly and no hard escalation was raised (e.g. a lone `gate_failed`); surfaced explicitly rather than silently skipped.
- **`held:land-failed`** — the in-flow land step itself failed (non-stale failure; distinct from `land_stale`) **or the land dispatch died / returned an unrouted result** — a dispatch that died producing no `MergeResult` routes here with `reason:'error'`, `detail:null`; the Lead re-runs the land manually per [references/resume-and-recovery.md](resume-and-recovery.md) §4.3's root-cause branches.
- **`held:phase-incomplete`** — the Workflow returned a non-`completed` notification (timeout, kill, infra death); the phase did not finish. Retryable via `resumeFromRunId` up to `run.roundLimit` total attempts; never advances the DAG; git state preserved (no teardown).
- **`held:workflow-error`** — the Workflow completed but returned a missing/unparseable result or a `landDecision` not in the known set, **or** the in-script top-level `try/catch` caught an uncaught exception inside the phase body (returned directly by the catch with a `workflowError` field). Terminal — HARD-halts regardless of `--afk`; never retried; git state preserved.
- **`held:submodule-pr`** — the submodule phase's land chose 2B (PR-and-hold): the refiner pushed the submodule integration branch and opened a PR on the submodule remote. **Set directly** by the Workflow (same pattern as `held:workflow-error` — **not** via `HARD_ESCALATION_REASONS`; DP2). The PR number and remote are captured in the ledger (`pr_number`, `pr_remote`). The run is held until a human merges the PR; resume reads `gh pr view <n> --json state,mergeCommit -R <pr_remote>`, takes `mergeCommit.oid` as `submodule_merge_sha`, writes it to the ledger, and clears the hold. Only arises in non-AFK 2B (an un-owned submodule under `--afk` is refused at launch — DP5).

Pin-transfer uses a flat `PIN_TRANSFER` schema for Workflow API compatibility; its consumer enforces status-specific evidence: Success evidence is mandatory: transferred requires a usable rebased tip, non-empty equal patch IDs and independently equal exact content identities; otherwise a usable tip is fully re-audited. Every success-bearing status with an absent/malformed destination holds before any receipt or re-audit. An uncontradicted already_upstream also requires a usable dispatch base, non-empty PRE, explicit empty POST and non-empty valid matched commit SHAs; missing evidence holds. An error, missing or unknown status retains the ordinary merge fallback only for independently verified unchanged approved content or independently equal patch and exact content identities; changed content gets the full re-audit.

### Task audit pin conflicts (#2141 finalization amendment)

A task auditor resolves the actual task branch tip using read-only Git. After every
complete task panel (whose schema requires `audit_sha`), the Workflow independently dispatches `audit-pin` on
the normal refiner tier; a repair re-audit escalates its verification to
`agents.refiner.recovery`. The refiner resolves the branch and each reported object name
through Git, returning a full `head_sha` and a positional `pins` array (full SHAs or null).
Equal text and prefix containment alone never prove identity; ambiguous, nonexistent or
malformed reports are unresolved. The engine checks proof shape and correspondence and
requires every resolved pin to equal the branch tip. Original reports and full resolutions
remain in `auditLog`; unresolved findings also survive as diagnostic evidence.

Missing, malformed or conflicting evidence never becomes approval. One fresh roster
re-audit at the confirmed full SHA may repair initial/fix worker reports. A second
conflict or unusable Git result takes the existing shortfall path; transport death keeps
its site-named environment classification. A later gate/pin-transfer/ace-specific audit
must retain that operation's Git-resolved promised SHA. Post-merge execution-evidence
absence keeps ADR 0024's separate SOFT treatment.

### Citation soundness on every completion path (#2229)

The shared `citationSoundnessClause` accompanies ace, sweep and terminal re-audits.
A row's mechanical membership is necessary but insufficient to resolve a parked ask.
The reviewing seat must judge that the row rules the named trade-off; an unsound match
blocks that candidate, which follows its existing reject/discard path with the ask retained.
