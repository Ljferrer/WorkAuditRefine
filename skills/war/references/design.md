# WAR — Design

**Status:** Active. A portable, Claude-native re-implementation of Gas Town's worker/auditor/refinery/witness model. It is built only on Claude Code primitives (`Agent`, the `Workflow` tool, git worktrees, GitHub issues). It needs no Go binary, no Dolt and no beads. The shipped version lives in [`.claude-plugin/plugin.json`](../../../.claude-plugin/plugin.json).

This document is the spec of record. The runnable surface is [`../SKILL.md`](../SKILL.md); the agents are in `agents/`; the per-phase engine is [`../assets/workflow-template.js`](../assets/workflow-template.js). It is also an ADR 0042 eviction destination. The §4 step 3 default-roster sentence was byte-identical to its pre-eviction `SKILL.md` text through `on flagged code` **at eviction time** (2026-09-08). The bullet's trailing `;` became a period.

## 1. Topology
`Human ↔ Lead (main session = Mayor) ↔ Workflow → { war-worker, war-auditor, war-refiner }`. The Lead orchestrates, gates, and talks to the human; it **never edits code**. There is no separate orchestrator agent and no standalone Witness agent — those functions live in the Workflow's control flow and lifecycle hooks.

## 2. Substrate — hybrid
- **Workflow spine, one run per phase.** Holds the phase loop and *is* the serial merge queue (one merge at a time, by construction). The script has no shell/fs access — every git/test action is performed by a spawned agent.
- **Workers** = worktree-isolated `Agent`s (per-role model from `war-config.mjs` DEFAULTS, never restated here), one fresh per task.
- **Auditors** = read-only `Agent`s (per-role model from `war-config.mjs` DEFAULTS); independent by default, with **one rebuttal round** on a split. The Workflow realizes that round by re-spawning each seat with its peers' findings, a portable stand-in for live peer messaging. Split resolution is **rebuttal first, then fix round when all surviving blockers have a suggested_fix**. If every surviving blocker carries a concrete in-file `suggested_fix`, the panel dispatches one fix worker plus a full-roster re-audit at the new SHA. That loop is bounded by `run.roundLimit`, and approval is unanimous on the post-fix `audit_sha`. A fix-less survivor is decision-forked and escalates with its `escalate_reason` (ADR 0013, Decision log 2026-09-08).
- **Witness dissolved** into the Workflow + hooks + Lead.

### Why a Workflow, not the Agent Teams feature
WAR's coordination is **knowable in advance**: a phase loop, dependency waves, a serial merge queue and a severity gate. So it belongs in a deterministic script, not emergent agent negotiation. The `Workflow` tool delivers exactly that, plus what WAR leans on. It gives reproducible structure, resume with one authority + two advisory records (§6), and schema-validated audit verdicts. It gives lean **ephemeral** agents (spawn → one job → return → die, no idle inbox-pollers). It needs **no experimental flag**: it runs on the stock `Workflow` + `Agent` tools.

The experimental **Agent Teams** feature (gated by `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS`) buys three things WAR doesn't need. They are direct teammate-to-teammate `SendMessage`, mid-run human steering of a single long-lived agent, and dynamic task-claiming off a shared list. WAR realizes auditor disagreement as a **Workflow rebuttal round** (re-spawn each seat with its peers' findings, §2) instead of live messaging. The only capability genuinely given up is *live* SendMessage debate, parked in §12.

A Workflow also can't *be* a team's Lead. It's a script with no inbox, and its `agent()` children aren't addressable teammates. It coordinates ephemeral subagents by call-and-return, full stop. The two are distinct substrates, and the human Lead session is the only place they'd mix. Rule of thumb: **scripted, reproducible coordination → Workflow; emergent or interactive coordination → Teams.** WAR is firmly the former.

## 4. Per-phase flow
1. **Cut** `integration/phase-N` off the working branch.
2. **Work (waves):** topologically sort the phase's tasks into dependency waves (usually one). Per wave, fan out one `war-worker` per task into a named mutable worktree branched off the integration tip. The worker implements, writes/extends the plan's mapped tests, runs the gate green, commits, pushes. **Frozen-base scope note (ADR 0012):** the frozen phase base is HARD **for same-wave parallel tasks only**. A same-repo task with declared `deps` rebases its worktree onto the integration branch as its worker's first action (dep-wave visibility). A first-dispatch rebase is a pure fast-forward, and a resume-with-commits conflict returns `blocked`. `gitlink-bump` tasks are excluded (their dep merged in the submodule repo).
3. **Audit (per task):** independent read-only seats review the pinned `audit_sha`. Each entry in the task's **roster** is one seat (1–5 distinct lenses, per-seat depth). A lone seat hitting a Critical or low confidence union-widens (`autoEscalate`). It widens toward its own `widen` nomination when valid (those lenses at `deep` on the high seat tier, #2534). Else it widens to the default roster's lenses (the byte-identical default-roster-union fallback). Gate over verdicts: any open Critical/Major blocks; any `escalate` halts; all `approve` on one SHA = merge-eligible. A split triggers one rebuttal round → approve / agreed-block / a surviving blocker with a `suggested_fix` → `FIX_NEEDED` (step 4) / a fix-less survivor → escalate. A seat conflict preserves an operator `ask` while held. A seat conflict has one locus, severities split across the blocking line, and a mandate-shaped or adjudication-match rationale on one side. No conflict bypasses the fix, fix-less, unchanged-survivor or finding-less-seat checks. The default roster is five seats (correctness / cascading-impact / plan-faithfulness / simplicity / performance) at `deep`; swap or add a domain lens (e.g. security, healthcare-safety) on flagged code. A seat names a `tier` (#2534). `high` runs `agents.auditor.high`, lifted to the auditor tier when it ranks below the auditor model. `low` or no tier runs `agents.auditor.low`, else the auditor model. A seat may carry its own `model`/`effort` (#2519): it overrides its tier for that seat only. In a rebuttal round a configured `agents.auditor.rebuttal` replaces the seat's own model/effort too. The auditor default is sonnet ([ADR 0056](../../../docs/adr/0056-default-seat-models-follow-the-2497-routing.md)). So give a boundary-heavy seat (security, parsing, Git or filesystem, recovery or state-machine work) `tier: "high"`, and `model: "opus"` too if its resolved model still ranks below opus. Raise only a seat whose resolved model ranks below opus (`MODEL_RANK` in `war-config.mjs`): an explicit pin below opus rises, and a `fable` tier stays.
4. **Fix loop:** a block routes a batched `FIX_NEEDED` to a fresh fix-worker on the *same* worktree, then a re-audit against the new SHA. The loop allows ≤ `round_limit=6` fixes, each one audited, then `audit-blocked` with the last audit's blockers named.
5. **Refine (serial):** `war-refiner` rebases each approved task onto the integration tip, re-runs the gate, merges it as one `--no-ff` merge commit carrying `WAR-Task: <task branch>` — one at a time. This sequencing *is* the merge queue.
6. **Land:** `war-refiner` merges `integration/phase-N` → working `--no-ff` (one phase commit), pushes working. Held if a hard escalation is open.
7. **Checkpoint:** Lead posts the phase report (also mirrored as a comment on the phase epic issue) and waits for your go (or notifies + proceeds under `--afk`).

## 5. Escalate (halt) vs resolve in-band
- **Escalate** — the plan is wrong/underspecified. The plan contradicts the code or itself, or a named interface/file the plan assumes is absent or different. Other cases: an ambiguity with >1 non-equivalent resolution; an ADR-worthy deviation; `audit-blocked` (round_limit); an unresolvable rebase conflict.
- **In-band** (handled silently by workers/auditors): bugs, style, missing tests, local refactors, neighbor-impact fixes.

## 6. State & resume

**One authority, two durable advisory records** ([ADR-0008](../../../docs/adr/0008-git-is-the-resume-source-of-truth.md)).

**Precedence: git branch state > GitHub issue labels > `ledger.json`.**

- **Git branch state** — the de-facto authority. The refiner's push-first CAS never `--force`es a shared branch, so the integration/working branches are monotonic. A recorded merge is real *iff* its SHA is reachable on the branch. Git can only *lag* (a crash before push), never be *wrong*.
- **GitHub issues** — human-visible task truth (labels in [`schemas.md`](schemas.md)). Remote-durable and human-visible; survive a local wipe. Advisory: repaired toward git on resume.
- **`ledger.json`** (`.claude/teams/<run-id>/`, uncommitted) — DAG, worktree/branch map, SHAs, verdicts, escalations. The richest record but the weakest authority — local, uncommitted, written by no code, a **lagging view**. A rendered `ledger.md` is the eyeball view. Advisory: repaired toward git on resume.
- **Workflow `resumeFromRunId`** — **off-ladder**: an intra-phase replay cache, not a landed-state record. A resumed phase re-runs the gate and the push-first CAS, so a stale cached "merged" is caught at re-land and never trusted. No reconciliation is defined for it.

Before resuming, the Lead runs the **Resume reconciliation pre-flight** (see `SKILL.md` Resume section). It is a read-only cross-check: it repairs the lagging layers toward git and halts on any unexplained commit (class C). Repair is one-way — records are rewritten toward git; no step mutates git to match a record.

**Submodule remote as co-source-of-truth** ([ADR-0010](../../../docs/adr/0010-submodule-landing-authority.md)). The same monotonicity argument holds for the submodule remote. The submodule's own push-first CAS never force-pushes its branch. So the gitlink SHA recorded in the ledger is authoritative *iff* it is reachable on the submodule remote. The reconciliation pre-flight extends to verify this. A ledger-recorded gitlink SHA *not* reachable on the submodule remote is class A: the pin never landed, so re-queue the bump task. The ledger gains submodule PR/SHA fields; these are advisory, authoritative-when-reachable — the same rule as `merge_sha` ([`schemas.md`](schemas.md)).

Durable product artifacts: phase reports/escalations → epic-issue comments; ADR-worthy deviations → `docs/adr/`.

## 7. Branch & worktree model
- One mutable worktree per task (worker + its fix-workers share it; it persists until the task lands so kick-backs can fix in place). Cleaned up after the task merges.
- Auditors read files through Read/Grep/Glob and compute the diff through read-only git Bash (no checkout to mutate). The tool restriction guarantees read-only. A fail-closed PreToolUse guard (`hooks/validate-auditor-git.sh`) backs it and denies any Bash beyond allowlisted read-only git subcommands.
- Integration branch removed after the phase lands; worktrees of escalated/blocked tasks are kept for inspection.

## 8. Cost & models
Per-role models are the `war-config.mjs` DEFAULTS (the authority — `DEFAULTS.agents.<role>.model`), never restated here as literals that rot; Lead = session model. Concurrency = the Workflow default (`min(16, cores−2)`), optionally capped per run by `run.maxParallel`. That cap is one global counting semaphore on agent dispatches in flight across the whole run, nested fan-outs included. Absent = no engine-side cap beyond the Workflow default, and shape/default live in `war-config.mjs`, never restated here. The **< 3× single-agent cost** target is a design aspiration, never asserted per preset here. The three presets differ in model mix, and `PRESETS` in `war-config.mjs` is the authority. `agentMatrix()` and `workerTierMatrix()` enumerate the phase roles and worker tiers. Neither helper enumerates the auditor rebuttal, high and low tiers, the red-team, snipe, snipe low, trial and helper tiers, or the skill seats (`SKILL_SEATS`). Read `DEFAULTS` and `PRESETS` directly for those. Any multi-seat roster is expected to exceed the target. `/war-review` reports a run's absolute token and tool-call totals for the operator to judge it against.

## 9. Harness notes (ECC / OmniEMR first run)
- **GateGuard** present-and-retry: workers/refiners present the requested facts then retry the identical Bash/Write op.
- **No `temperature`** on current Opus/Fable — any SDK call a worker writes must omit it.
- We may run *inside* a Claude worktree already; nested worktrees off the working branch use absolute paths and avoid `.claude/worktrees/` collisions.

## 10. What WAR keeps / drops / changes vs Gas Town
- **Keeps:** the four roles and the Nun gate's fail-closed convergent unanimity + severity + the multi-lens roster + plan-faithfulness. It also keeps integration-branch waves + `--no-ff` land, GUPP propulsion, the read-only-by-construction auditor.
- **Drops:** the Go orchestrator, Dolt/beads, `gt mail`/nudge, the standalone Witness/Deacon daemons. It also drops tmux session management.
- **Changes:** durable state → GitHub issues + a JSON ledger; propulsion → Workflow control flow (no polling). Auditor read-only → tool restriction (Read/Grep/Glob + a fail-closed guard restricting Bash to read-only git) instead of detached-checkout-push-unset. The merge queue → a serial Workflow loop instead of batch-then-bisect.

## 11. Validation criteria
- Lead never edits code (only orchestrates/gates). · Auditors cannot write/commit/push. · A task can't merge with an open Critical/Major, without a green gate, or before unanimous audit on one SHA. **Pre-ace probe carve-out (PIN-3):** a blocker that preAceProbe proves was there before the ace leaves that re-audit. It rides the late-fix pass instead, so it never holds the ace or the merge. A seat conflict with no fix parks its ask and still holds the phase on purpose; a fixable blocker takes a fix round first (#2557). · "Green by deletion" is caught and escalated. · A killed Lead resumes from ledger + issues. · Each phase lands as one `--no-ff` commit; the run ends in exactly one PR. · `/cost` reported per run from `/war-review` totals; the < 3× single-agent figure is the section 8 aspiration, not a gate.

## 12. Deferred (post-v1)
- Batch-then-bisect merge queue.
- Live-SendMessage audit debate.
- Multiple concurrent phases.
- Multi-repo.
- Per-task GitHub PRs as the review surface.
- Learned roster seeding (flagging high-blast-radius tasks from history).

## 13. v0.2.0 amendments
- **Issue timing:** file **all phase epics up front** at the approval gate (full scope before any teammate launches). Break each phase into **task sub-issues just-in-time** at that phase's start. So later phases absorb earlier phases' learnings and plan drift, while still honoring "write all issues before launching any teammates" at the epic level.
- **New role — `war-servitor`** (model per `war-config.mjs` DEFAULTS): after a phase *lands*, a single write-mode pass captures **durable learnings** into the **local memory root**. That root is the absolute `memoryLocalRoot` threaded at Setup (`~/.claude/projects/<proj>/memory/`, one file per fact). `type: project` marks a file promotable, but *every* file is written locally. Repo-root publication is the Lead's Gate-2 promotion, never a servitor write. It is fed the phase's audit log + escalations. Auditors stay **read-only**, and the servitor is the only reviewer-side writer. Its capability allowlist confines its writes to the local memory root. It has no Bash, only Read/Grep/Glob/Write/Edit plus the read-only memory query tool. The PreToolUse scope hook gates the residual Write/Edit paths by `agent_type` to the local memory path-pattern. It also denies mutation of any pre-existing untagged memory file ([ADR 0002](../../../docs/adr/0002-scope-by-agent-type.md), [ADR 0022](../../../docs/adr/0022-servitor-local-root-writes-gate-2-promotion.md)). Cadence: **once per phase** (not per task). Captures signal only — gotchas, plan↔code mismatches, deviations+why, patterns — never routine "implemented X" notes.
- **Roles table** now includes Servitor (→ Gas Town's `bd remember`).
- **Flow** gains a **Wrap-up** stage after Land; the Workflow returns `servitorResult` alongside `{ landed, escalated, minorsFiled, landResult }`.

## 14. v0.3.0 amendments
- **New skill — `/war-room`** (conversation-only): interviews the user from a preset (balanced/thorough/economy) plus targeted overrides, and writes a run config to `.claude/war/config.json`. It never decomposes a plan or launches `/war`.
- **Config surface.** `skills/war/assets/war-config.mjs` owns the schema, defaults, presets, and validation (a single tested source of truth, used by both skills). The `/war` Lead loads and validates the config in Setup, applies non-null `overrides`, and threads `agents` / `audit` / `run` (and `routing` when set) into the per-phase Workflow `args`. `workflow-template.js` reads those instead of hardcoded model literals.
- **Configurable knobs:** per-role `model` (opus/sonnet/haiku/fable) and `effort` (default…max, where `max` = "ultrathink"). `roster` (1–5 distinct-lens seats, per-seat depth) with `rosterPolicy` (auto/all/solo) seeding per-task rosters. `autoEscalate` (set `false` with `rosterPolicy: "solo"` to pin exactly one auditor); `roundLimit`; `afk`.
- **Backward compatible.** No config file → byte-for-byte the pre-v0.3.0 behavior (`effort: "default"` passes no effort opt; built-in model defaults unchanged).

## 15. v0.4.0 amendments
- **New sibling skill — `/red-team`** (completes the trilogy): `/war-room` configures a run → **`/red-team` hardens the plan** → `/war` executes it. It runs *before* `/war`, attacking the input plan so WAR fans out over claims that have been **proven, not assumed**. Conversation-driven + Workflow-backed; **not** part of `/war`'s per-phase engine, which is unchanged.
- **Spine + bespoke probes.** Derives a universal spine of adversarial lenses (claims-vs-reality, executable-proof, coverage-vs-source, consistency-placeholders, dependency-feasibility) plus plan-tailored probes. It **proves** each claim by running the plan's tests/edits/commands in **throwaway sandboxes** (temp dirs / git worktrees) — never touching the target repo. Analysis lenses use the read-only `Explore` agent; execution probes run isolated.
- **Prove-don't-assert (`adversarial-confirm`).** A blocking finding is **downgraded to a warning unless an independent confirm agent reproduces it**. This is the Nun gate's fail-closed-on-evidence discipline applied to plan verification, surfaced as the named `adversarial-confirm` Workflow stage.
- **Outcome:** grills the user on every blocker and patches the plan **in place** until it reaches a gate-emitted proceed verdict. That verdict is **CLEARED**, or **ADJUDICATED** when a patched blocker was not re-verified by a probe re-run ([ADR 0043](../../../docs/adr/0043-adjudicated-clear-distinct-terminal-verdict.md)). It leaves a report under `docs/red-team/`.
- **Surface.** `skills/red-team/` — `assets/red-team-gate.mjs` (verdict + severity-classify logic, tested), `assets/workflow-scaffold.js` (copy-per-plan Workflow: spine + probes + adversarial-confirm), `references/lenses.md`, `SKILL.md` runbook. Those maintained surfaces are the design's home (spec-posterity rule, ADR 0046). v0.4.0 is purely additive (new front-end skill + version bump).

## 16. v0.4.1 amendments
- **Land-path-agnostic Wrap-up.** The servitor's Wrap-up is now an obligation owed **by whichever path lands the phase**, not a stage welded to the in-flow land. The template surfaces `landDecision` (the `KNOWN_LAND_DECISIONS` set) and the `auditLog` in its return. Since #2702 it runs the Wrap-up itself on `landed`, `held:escalation` and `held:land-failed` when `memoryLocalRoot` was threaded. On a hold the anchor is the last merge tip and the decision stays a hold. On any other `held:*` decision the Lead lands manually (the human-owned boundary, unchanged). Then it runs `war-servitor` itself with the returned `auditLog` + escalations + resolution. Guard: skip the Lead pass only when the in-flow Wrap-up ran on `landed`; after a manual or recovery land of a held phase the Lead runs one more resolution-fed pass, even when `servitorResult` is set.
- **No silent land.** The previously-unlogged `landed.length === 0 && !hardEscalation` case is now `held:nothing-merged` with an explicit log; the land decision is observable in every run. The hard-escalation hold set (`escalate`/`audit-blocked`/`conflict`) is unchanged — `gate_failed`/`error` still do not, by themselves, block a land that has other merged tasks.
- **decideLand** is the canonical, unit-tested decision (`assets/land-decision.mjs`), mirrored inline in `assets/workflow-template.js` (the Workflow sandbox can't import) — keep in sync, same pattern as `ROLE_MODEL`.

## 17. v0.6.0 amendments
- **Refinery now operates in `_refinery`.** Every `war-refiner` merge — the integration-side of merge-task and the working-branch land — runs inside a run-scoped **refinery worktree** at `<worktreeRoot>/<runId>/_refinery`. The refiner never runs `git merge`, `git checkout`, `git update-ref`, or `git push` against the Lead's main checkout. See [ADR-0004](../../../docs/adr/0004-refinery-merges-in-a-worktree.md).
- **Land is push-first (the CAS).** The working branch is checked out in the Lead's cwd and cannot be checked out again. So the land runs in a **detached** `_refinery` at the working tip. The `git push` (no `--force`) is the atomic compare-and-swap against shared truth. The local `refs/heads/<working>` is advanced as a follower only on push success.
- **`land_stale` joins the hard-escalation set.** When same-branch land contention exhausts `roundLimit` relands, the result is `land_stale` — a distinct hard-escalation status for CAS-topology failure, held for the Lead. It is not `conflict` (which is a merge-text failure). Added to `HARD_ESCALATION_REASONS` in `land-decision.mjs` and mirrored inline in `workflow-template.js`.
- **§12 scope update.** "Multiple concurrent runs in one repo" (previously fully deferred) is now **partially in-scope**. The Refinery's write surface is isolated, so two runs on different working branches land without contention and without serialization. Multi-repo and concurrent-phases remain deferred.

## 18. Clean-handoff amendments (ADR 0012/0013)

- **Disposition routing (ADR 0013) — classify-at-collection.** Every Minor/Nit finding routes **once**, by auditor-owned `disposition`, orthogonal to severity. `absorb` is mechanical and intent-consistent, executed in-phase. `follow-up` files a `war-followup` issue, and the auditor must state why it is not absorbable. `note` (phase report + servitor feed) never files an issue, and a `behavior` note never stays a note. With a fix on a named file it becomes `absorb`, else a parked `ask` (ADR 0058). `ask` (#1550, ADR 0013 amendment 2026-08-25) is a decision-shaped Minor/Nit only the operator can rule. It carries the mandatory question+fork field, parks on the run's `asks[]`, and is ruled at the Checkpoint strike-list gate: **never filed unruled**. Since the ADR 0013 amendment 2026-08-27 a ruled ask whose fix is fully specified **executes in-run**. It files Lead-side with filing parity **only** on cannot-execute or execution-failure. A fully specified Minor/Nit defaults to `absorb` in the task diff and to `absorb` + `phaseClose:true` outside it. `follow-up` is legal only with a `BARRIER_TOKENS` tag in the structured `barrier` field (ADR 0013 amendment 2026-09-04). Omitted → Minor becomes follow-up, Nit becomes note; `ask` is never a default. Legacy `autoFixable:true` reads as `absorb` for one release (deprecated). `minorsFiled` receives only `follow-up`; a `notes` array receives `note`; `asks` receives `ask`. `asks` rides the top-level return beside `minorsFiled` and the handoff's ninth (lossy) `asks` key. It is excluded from the follow-up consolidation and the `file-followups` dispatch. This **replaced** the old eager `minorsFiled` push + aced-splice mechanics. The **terminal-disposition demotion ladder** guarantees zero unrouted findings on every exit path, now **per subset**. Demote one step toward durability, never drop silently, and log every demotion. A failed absorb → follow-up. Findings on a task that never reaches the approve branch → follow-up, filed with the escalation. A held phase's queue → drained to follow-up; a fileless absorb → its severity default. `demote()` **refuses an ask** unconditionally and loudly: log() + re-route onto `asks[]` (exactly-once by finding identity). It never routes to `minorsFiled`/`notes` and never throws. The sole lawful ask→follow-up conversion is the Checkpoint `--afk` no-match arm, Lead-side, question preserved. An ace re-audit **regression** no longer demotes the whole batch. The bounded **ace bisection** ladder (canonical: `aceBisect` in `skills/war/assets/workflow-template.js`) salvages the good majority, and only finally-failing subsets demote. It runs culprit-first excision and serial subset re-application at the tip, at depth ≤ 2. It never splits same-file findings, and it forward-reverts failed tips in-loop. The subsets still queued when the **absorb budget** is spent mid-bisection ride to the phase-close sweep as absorbs (`routeToSweep`, `phaseClose: true`), logged, by design. The budget is `absorbRounds < run.absorbRounds`, the per-task ace meter separate from `fixRounds` (ADR 0013 amendment 2026-09-03). Every ace-side commit (batch, subset, re-entry) charges one `absorbRounds` slot and carries an `Ace-Charge: <task>:<n>` trailer. `fixRounds` counts blocking fix rounds and floor retries only, and the batch ace reads the same budget gate. **Budget-bounded re-entry (ADR 0013 amendment 2026-08-27)** is the adjacent vehicle bounded by that same gate. A fresh `absorb` born at a WAVE-SIDE re-audit dispatches another ace-style batch on the same machinery. That re-audit is plain, bisection-subset, or a re-entry batch's own. Its canonical home is `aceReentry` in `skills/war/assets/workflow-template.js`, with no new round type. It runs while `absorbRounds < run.absorbRounds`, and that budget is its sole bound **for the three wave-side re-audit sources**. The **merge-slot pin-transfer mismatch re-audit** is a fourth source that never re-enters at all. The merge-slot floor-fix re-audit and the late-fix pass re-audit are further such sources. Each routes its absorb-eligible findings straight to the sweep via `routeReauditMinors`' `noReentry` opt, unconditional on budget headroom. The exception is a late-fix re-audit `behavior` absorb. It carries on `carriedTasks[]` (non-final) or files "raised after the late-fix pass" (final), PIN-21. Budget spent, **the re-entering finding** routes `phaseClose: true` to the phase-close sweep ⇒ sweep-discard ⇒ `follow-up`. That is the same sweep rung a still-queued bisection subset and a budget-spent batch ace take (`routeToSweep`). `routeToSweep` is the sole producer on the FINDING path. It is reachable from the ace-ladder arms (spent budget, ace off, a failed attempt) and an out-of-diff absorb. It is also reachable from `routeReauditMinors`, the held-absorb drain, the fenced-row route before an ADVISORY POLISH dispatch, and the gate-audit family's absorbs. The ruled-ask intake mints `phaseClose: true` directly on its own entries (D15(b)). A forward-reverted finding never re-enters, and every demotion is logged. **Absorb-by-citation** rides that vehicle under `--afk`. A parked ask matching a standing adjudication row on its NAMED trade-off resolves to an executed absorb. Its durable record carries the row-id + match rationale. The re-audit panel owns the soundness duty, and an unsound citation is blocking: the batch reverts, and the finding demotes naming the mismatch. The ace's orchestrator backstop **narrowed** to the two pure version-slot JSONs. Release-slot eligibility is by literal, not by file (D20, #2000). So only the `RELEASE_SLOT_FILES` basenames (`plugin.json`/`marketplace.json`, canonical in `skills/war/assets/land-decision.mjs`) refuse by filename. A `README.md` or `CHANGELOG.md` absorb rides the per-task ace like any other absorb if it moves no version literal, CHANGELOG head heading or README `## Status` version token. `version-slots.test.mjs` in the gate is the merge guard.
- **Phase-close coherence sweep (ADR 0012) — fail-open, at the integrated tip.** Runs **after** the land decision is computed and **before** the land dispatch, iff `landDecision === 'landed'` and the `phaseCloseQueue` is non-empty. The refiner provisions a `p<N>-polish` worktree (branch `war/<slug>/p<N>-polish`) at the post-merge integrated tip via the existing `ensure-worktree`. **One** war-worker drains the queue verbatim, plus each sibling site of a queued defect class. It makes one commit with touched tests, no version-slot literals and no ad-hoc seam hunting. The **full config-default roster** re-audits the polish SHA under the same unanimity rules (the Lead may not downgrade it). Re-approved → merged at the serial queue's tail, the land proceeds on the polished tip, the queue is recorded on `aced` at the polish SHA. Anything else → **discard**: branch + worktree left in place (reaping is a human act), queue demoted to follow-up. The pre-polish tip lands exactly as it would have, and a discarded sweep recomputes nothing. Bookkeeping is a Lead-side task-grade ledger entry + the handoff block. There is **no owned-refs registration**: the spec's §4.5.5 described machinery that does not exist.
- **Intent threading + handoff (ADR 0013).** `args.intent` (string|null) is the plan's `## Commander's Intent` or `## AI-Commander's Intent`. Either heading works, Lead-extracted verbatim, never Lead-invented except by `/war-machine --afk` (ADR 0014). It threads into worker, auditor, ace/sweep, gate-audit, and servitor prompts: plan slice = floor, intent = ceiling. `null` ⇒ byte-identical intent-less prompts (literal behavior). The gate-audit pass also verifies the phase's claimed End-state conditions at the confirmed tip **artifact-first**. That rule comes from the 2026-08-05 precision-chain plan. The refiner's **land-barrier endstate-check dispatch** executes a `check:`-tagged condition once per phase. It runs after the serial merge queue's last merge, before the gate-audit seats spawn. It tees one per-condition artifact (`_refinery/.war/endstate-<phaseId>-<n>.log`, stamped with the tip SHA it ran at). Seats read the artifacts (a `gate:`-tagged condition attests from the captured gate logs). They return one `endStateAttestations` row per claimed condition (`status: met | unmet | unverified` plus cited evidence, never a bare verdict). Findings stay defect-only. A condition provably unmet at the confirmed tip is a Critical/Major finding. It is HARD when its suggested_fix is blank or a no-fix sentinel, otherwise it joins the late-fix pass (gateHardOf, ADR 0058). A condition owned by a later phase is out-of-scope, never a hold. So is one owned by a deps-chained sibling task of the same phase not yet landed at the audit's scope. When no task is gate-auditable but conditions are claimed, ONE End-state-only seat spawns and consumes the same artifacts. The handoff maps a condition **no seat attests** to `unverified`, never `met` (whole-pass absence stays all-`deferred`). The return gains `notes` and — on `landed`, `held:escalation` and `held:land-failed` only (#2702) — the machine-readable `handoff` block (see `schemas.md`).

## 19. Confirmation-only dispatch inventory (dated 2026-11-08, #2554)

A confirmation-only dispatch spawns an agent only to read back from Git a result the engine already
holds or was just told. Its reply changes a decision only when the read disagrees with the claim. The
Workflow sandbox has no shell, so every Git read costs one dispatch. Each row names its site by its
`dispatchKind` and label literal in `workflow-template.js`, never by a line number. The verdict is one
of four. **keep**: the read is already minimal. **script it**: one tested script prints the proof, so the
dispatch runs one command on the helper card. **moved to the helper**: a later plan runs the
dispatch on the helper card, whose guard admits no script. The fourth is **remove**. This table removes nothing. The Deferred
validations backstop on this table (row 6 of the plan 2026-11-08-auditor-and-worker-guard-habits) is
its drift check. Each
"script it" or "remove" row becomes its own follow-up issue. It is a dated inventory, not a contract:
when an engine change renames a `dispatchKind` or label, grep each row's literals and correct the row.
