# WAR — Work · Audit · Refine

You are the **Lead** (the Mayor). You orchestrate and gate; you **never implement code yourself**. WAR is a Claude-native re-implementation of Gas Town's worker/auditor/refinery/witness model built on `Agent`, the `Workflow` tool, git worktrees, and GitHub issues — no Go binary, no Dolt, no beads.

Full architecture: [references/design.md](references/design.md). Data contracts: [references/schemas.md](references/schemas.md). Gas Town lineage + tunables: [references/gastown-design-params.md](references/gastown-design-params.md). When re-baselining prompt-surface budgets (an operator act — never a worker's), read [references/budget-rebaseline.md](references/budget-rebaseline.md).

## Quick start
```
/war <plan-file> [--working <branch>] [--landing <branch>] [--campaign-ordinal <K>] [--afk] [--ace] [--config <path>]
```
`--ace` sets `run.ace = true` for this run (Lead-side, one-off override, same shape as `--working`/`--landing` — no code parser; `/war` is skill-driven). See the ace behavior in **Per phase → Audits/Refines** below.
`--afk` sets `run.afk = true` for this run (Lead-side, one-off override over the config default, same shape as `--ace`/`--working`) — the engine reads it as the operator-presence gate on the absorb-by-citation unpark (#1879 RULING 1).
Example: `/war docs/implement/implementation_plan_A.md --working dev/planA --landing master`

## Setup (once)
1. **Load the run config (if any).** If `.claude/war/config.json` exists (or the user passed `--config <path>`), resolve it: `node ${CLAUDE_PLUGIN_ROOT}/skills/war/assets/war-config.mjs <path> --fill-defaults`. If it exits non-zero, **stop and show the errors** (don't run with a broken config). Announce `using config from <path> (profile: <profile>)`. The resolved config supplies `agents`, `audit`, `run`, and any non-null `overrides`. With **no** config file, use built-in defaults — the `DEFAULTS` models from `war-config.mjs`, at session effort. The config is produced by `/war-room`.
2. Confirm a clean git repo with a GitHub remote and `gh` auth. Ask for the **working** and **landing** branches if not given (default working = current branch; landing = the repo's default branch). A non-null `overrides.workingBranch` / `overrides.landingBranch` wins over asking. This yields the **desired** working branch. **Crash-heal pre-flight (before `resolve-working-branch`):** scan `git worktree list` — when it shows a leftover `p*-publication` path or the desired working branch checked out anywhere unexpected, read [references/setup.md](references/setup.md) (§ Crash-heal pre-flight) and heal before resolving. Then resolve it against the launch context before use: run `bash ${CLAUDE_PLUGIN_ROOT}/skills/war/assets/provision-worktrees.sh resolve-working-branch <desired> <slug> <date>` (the single tested owner of git-topology; never re-implement its checkout detection or branch cut in prose) and take its stdout as **the run's working branch**. When the desired branch is checked out in **any** worktree (the launch-worktree collision — un-advanceable by the refiner's push-first CAS), it returns a fresh dedicated `dev/<date>-<slug>` branch checked out nowhere — or, when a leaf branch `dev` blocks that namespace (D12, #1380), the flat fallback `war-<date>-<slug>` (same tip, ownership recorded; a resume reuses whichever owned candidate exists; a cut that still dies names the blocking ref + the `--working` remedy); otherwise it echoes `<desired>` unchanged. On both paths the subcommand first validates `war/<planSlug>` cuttability, dying actionably at Setup — naming the blocking leaf (`war` or `war/<slug>`) and the remedy (a different plan slug, or delete/rename the leaf) — before any phase launches (D14). Then bootstrap the resolved branch on origin before Phase 1: `bash ${CLAUDE_PLUGIN_ROOT}/skills/war/assets/provision-worktrees.sh ensure-origin <resolved>` (idempotent — a branch already on origin is a no-op, never a force). **Announce** `using working branch <resolved> …` and **record** `<resolved>` in the ledger as the run working branch.
3. Detect the **declared gate**: `pyproject.toml` → `uv sync && ruff check && pytest`; `package.json` → its lint/test scripts; else **ask once** and record it. A non-null `overrides.gate` (the *declared base*) wins. Then **resolve it**: run `node ${CLAUDE_PLUGIN_ROOT}/skills/war/assets/war-config.mjs --resolve-gate "<declared>"` and thread the **result** as the gate — this self-discovering command appends a bash-suite discovery loop so every `*.test.sh` in the repo is found and run on each invocation (re-detection is automatic; no manual re-detect step needed after an intra-phase merge adds a new suite). Never run a phase without the resolved gate. As a **belt-and-suspenders backstop**, the Workflow engine now **normalizes the dispatched `plan.gate` through the same idempotent composition at entry** (its gate composition point), so a missed pre-resolution can no longer ship a shell-blind gate — the Lead pre-resolution is the belt, the engine normalization the suspenders.
   - **Opt-in docker gate (spec §4.3):** when any Dockerfile exists in the repo (basename `Dockerfile` / `Dockerfile.*` / `*.Dockerfile`, excluding `node_modules/` and `.git/` — the packaging floor's shared discovery expression, ADR 0006), read [references/docker-gate.md](references/docker-gate.md) and follow its daemon-probe → probe-build → include / trim / defer routing (`--afk` arms included) before finalizing the gate.
   - **Test-floor pattern (ADR 0006 floor ⊆ gate).** Propose the run's **test-floor glob set** together with the gate — floor ⊆ gate is **one Setup decision**, so the operator confirms both at once (`--afk` takes the proposal) — though under `--afk` that confirmation is not the final word on the *value*: a proposal the sanity floor below rejects becomes a **pending proposal**, re-checked (and possibly adopted — never re-asked) at each phase launch (see the per-phase pending-proposal re-check under "Run one Workflow per phase"). Derive it from **named detection inputs**: the target's test-runner config — `package.json` (`scripts.test`, test-framework devDependencies), `vitest.config.*` / `jest.config.*`, `pyproject.toml` `[tool.pytest]` — **and** a `Glob` sample of the test files actually on disk (the convention really there, not just declared). Propose **single-star tokens** whose star is **leading** (e.g. `'*.test.ts *.test.tsx'`): under the floor's bash-`case` glob matcher `*` crosses `/`, so a **leading**-star token covers root **and** nested files, whereas a `**/`-prefixed token (`'**/*.test.ts'`) misses root-level files and a path-prefixed star (`'src/*.test.ts'`) can never match a root-level file at all. **Unknown convention → `null`** (today's hardcoded floor defaults, byte-identical). Record the confirmed value in `overrides.testPattern`; the floor always unions the gate's unconditional `*.test.sh` discovery, so no custom set can make it exceed the gate. **Non-goal:** the pattern is **never parsed out of the gate command** — it rides config, pinned beside the gate at Setup exactly as `plan.gate` does (an `--afk`-adopted value is threaded per phase, see the re-check below).
     - **`--afk` sanity floor:** under `--afk`, before taking the proposed test-floor pattern, read [references/setup.md](references/setup.md) (§ `--afk` sanity floor) — the reject-to-`null` rule and the pending-proposal ledger record live there.
4. Resolve the **two memory roots** for this run (spec §4.1; the old either/or fallback is retired), **both to absolute paths at Setup**: the **local root** expands `~` to `~/.claude/projects/<proj>/memory/` (private, never committed, always creatable); the **repo root** (`docs/learnings/`) resolves against the launch checkout (read path unchanged). A non-null `overrides.learningsTarget` overrides the **repo-root path** — it is the read-path repo root (feeding the worker self-query `--repo`) **and** the Gate-2 promotion destination. Record both roots in the ledger. Thread **`memoryLocalRoot`** (the absolute local root — the servitor's *only* writable path) into every per-phase Workflow alongside the retained `learningsTarget` (the read-path repo root). **Omission producer:** when the step-5 memory probe reports memory disabled, `memoryLocalRoot` is omitted from the args and every phase's Wrap-up self-skips with a logged line (fail-open). The servitor writes *every* lesson file under the local root and routes each by `type` (§4.6); the Lead's post-servitor Gate 2 promotes the `type: project` files into the repo root per the `commitLearnings` decision.
   - **Setup seed render (idempotent).** When the **resolved** repo root exists on disk and the local `MEMORY.md` is missing or carries no `[repo]`-marked rows, run once: `node ${CLAUDE_PLUGIN_ROOT}/skills/_shared/war-memory.mjs render-index --local <local root> --repo <resolved repo root>`. This projects the repo's published lessons into the local `MEMORY.md` so a fresh cloner's first `/war` (and the cloner's non-WAR sessions) sees them before phase 1 dispatches. **Runs even when `memory.retrieval` is false** — seeding is a render, not a retrieval; it is skipped only when the Node probe (step 5) reports memory unavailable (Node < 24 / no `node:sqlite`). Use the **resolved** repo root (honors `overrides.learningsTarget`), never a hardcoded `docs/learnings`.
5. Probe the memory CLI: `node ${CLAUDE_PLUGIN_ROOT}/skills/_shared/war-memory.mjs query 'probe' >/dev/null 2>&1`. On any non-zero exit (Node < 24 has no `node:sqlite` — the CLI prints `war-memory: requires node:sqlite (Node >= 24); memory features disabled`), record **memory disabled** and skip the prefetch (§below) and the post-servitor render/commit steps for the whole run. Memory **fails open** — a missing CLI never blocks a WAR run.
6. Create the run ledger `.claude/teams/<run-id>/ledger.json` (+ a rendered `ledger.md`). The ledger is the richest per-task record (SHAs, verdicts, worktree map), but **not the authoritative** resume source. On resume, the precedence is: **git branch state > GitHub issue labels > `ledger.json`**. Git wins because the refiner's push-first CAS never `--force`es a shared branch, so the integration/working branches are monotonic — a recorded merge is real iff its SHA is reachable on the branch; labels beat the ledger because they are remote-durable and human-visible (they survive a local wipe); the ledger is a **lagging view**. On resume, run the **reconciliation pre-flight** (see Resume procedure below) before reading the ledger or open issues and continuing.

## Decompose + approve — GATE (before any teammate launches)
1. Read the plan. Extract **phases** (prefer an explicit build-order/phase section, e.g. a "Build order"; else top-level sections) and propose the phase→task DAG. Also extract the plan's `## Commander's Intent` OR `## AI-Commander's Intent` section (either heading) **verbatim** and thread it as `args.intent` (string|null) into every per-phase Workflow, mapping its numbered End-state conditions to the phases that claim them (`phase.endState` — checked by the gate-audit pass). Stage each claimed condition as a row `{ condition, tag, check }` ([references/schemas.md](references/schemas.md)): `condition` is the verbatim condition text (extraction per ADR 0013/0014 — unchanged), `tag` is the condition's parsed D5 End-state tag (ADR 0044's End-state tag law: `check:` | `gate:` | `HARD at audit_sha` | `backstop:`), `check` is the executable command of a `check:`-tagged condition (`null` on every other row) — parsed from the FULL numbered condition (soft-wrapped continuation lines joined; the tag routinely sits on a continuation line), taking the backticked command span after the `check:` key and excluding trailing prose/punctuation. An untagged/bare condition normalizes to `{ condition, tag: null, check: null }` — the **judgment path**: gate-audit seats attest it from named observables, no command runs for it. The Lead parses tags, never mints them — a condition the plan left untagged stays on the judgment path (the legacy arm: a pre-tag-law plan stages every condition there and runs as before). Neither section present? Interactive: **ask at the approval gate** and transcribe the operator's answer. `--afk`: `intent = null` — the run degrades to literal plan behavior. The Lead **never** invents intent (ADR 0013); `/war-machine --afk` is the sole authoring surface allowed to (ADR 0014).
2. Seed each task's **roster** from `audit.rosterPolicy`: `all` → every task gets the full config roster (`audit.roster`); `solo` → every task gets `[{ lens: <first config lens>, depth: 'neighbors' }]`; `auto` (default) → **you compose 1–5 seats per task from the lens catalog** (any predefined lens is eligible, plus mintable domain lenses), each with an explicit per-seat depth (`neighbors`|`deep`) and a one-line rationale for the choice — deeper/broader on high-blast-radius tasks, a lone `neighbors` seat on leaf/low-risk ones. You can still hand-edit any task's roster at this gate. (`autoEscalate` still widens a lone seat's roster at runtime on a Critical/low-confidence finding — toward the auditor's `widen` nomination when it supplies a valid one, else the default roster's lenses — unless it is `false`.)
3. Set **`requiresTest`** per task (default `true`). Set `false` only for tasks with no executable surface: pure docs/config edits, VERIFY no-ops, or prose-only contract tasks. When `requiresTest:false`, the refiner's test-floor check is skipped for that task and the post-merge gate-audit pass **auto-skips** it (no mapped tests ⇒ its HARD path is vacuous; the skip is logged, never silent). For a pure-docs task, propose a solo `{ lens: 'correctness', depth: 'neighbors' }` roster (D4) — "needs no test" does not imply "needs little review", so this stays a proposal the human approves at the gate.
   - Also set **`requiresPackaging`** per task (default `true`; the refiner reads `r.task.requiresPackaging !== false`, independent of `requiresTest`). Set `false` only for a task that cannot add an image-shipped source file — pure metadata/docs edits, or a repo with no Dockerfile at all. When `false`, the refiner's packaging-floor check (`assert-packaging-in-diff.sh`) is skipped for that task; like the `requiresTest:false` skip it is **logged, never silent**.
   - Thread each task's plan **`Files:`** list into the per-phase Workflow as **`tasks[].files`** (the plan's declared file paths, **not** the worker's reported diff — the diff does not exist at dispatch time). The template's first-pass worker dispatch reads it: an **all-`*.md`** task (non-empty list, every entry ends `.md`) runs its worker on the **docs** tier (`agents.worker.docs`, sonnet by default); any non-`.md` entry — or an **absent/empty** list (the fail-safe: an undefined list never vacuously reads as docs-only) — keeps the base worker tier. Fix-round and `--ace` follow-up dispatch on the `agents.worker.fix` tier when configured, else the base worker.
   - **Done-when intake (the authoring template's done-when law made mechanical — ADR 0044).** Parse each task's `Done when:` bullet into the staged task shape as **`tasks[].doneWhen`** (string|null), alongside `requiresTest`/`deps` — the bullet's text AFTER the `Done when:` key, never the key itself, and the command inside its code span (backticks are markup, stripped exactly as the `Files:` list's are). A bullet parses as its **full bullet content**: soft-wrapped physical lines joined with single spaces until the next `- ` bullet or a blank line — the authoring template wraps its bullets, and a first-line-only parse truncates the command into a spurious `done-unmet` at merge. The template's no-command arm (`None — <basis>`) stages `doneWhen: null`, exactly like an absent bullet. A `requiresTest: true` task without a `Done when:` command is an **intake defect**: interactive runs **surface it at the approval gate** (the operator supplies the command or re-rules `requiresTest` — a real ruling, never silently defaulted); under `--afk` the Lead **refuses dispatch** (a hard stop before any teammate launches — the Lead never invents an acceptance command). **Legacy arm (checked first):** a plan with no `Done when:` bullets anywhere stages unchanged and the intake-defect rule does not fire — every task's `doneWhen` is `null`, dispatch proceeds, and downstream prompts stay byte-identical (the absent ⇒ `''` pattern).
   - when a staged task's `Files:` rewrites a doc that restates machine-source-derivable facts (config/manifest/enum/version slot), read [references/touched-doc-accuracy.md](references/touched-doc-accuracy.md) — the guard / de-mirror / explicitly-defer trichotomy the plan must already show for each such fact (touched-doc accuracy duty, ADR 0025 amendment; a silent restatement is a plan defect to surface at the approval gate).
4. **Backstop extraction — the Lead is the single normalization point (spec §4.4).** Parse the plan's `## Deferred validations (backstops)` section (or its AI-declared variant) into `{ check, why, runner, source: 'plan' }` entries — an entry line that does not parse into the three fields is **carried whole as `check`, never dropped**. Merge in any Setup auto-recorded entries (§ step 3 docker-gate, `source: 'auto'`). Mark `aiDeclared: true` on the plan entries **iff** the heading was the AI-declared variant (`## Deferred validations (backstops — AI-declared)`, ADR 0014 provenance — an AI-declared waiver is never later surfaced as operator-ratified). Thread the merged result as **`args.backstops`** (array|null of `{ check, why, runner, source, aiDeclared? }`) into every per-phase Workflow; the Workflow passes it through to `handoff.backstops[]` untouched **save one exception** — it appends a deduped `source: 'auto'` entry for any **baseline gate debt** it classifies mid-phase (spec §8; see the Checkpoint's `gate_failed` routing). Lead-normalized `source: 'plan'`/`source: 'auto'` entries are never rewritten. A legacy plan with **no** backstop section → `args.backstops = null` **and** the phase report notes "no backstop section (pre-ratified-backstop plan)". Interactive runs **ask at the approval gate** to confirm the extracted backstops; `--afk` takes them as parsed.
5. **Assemble, thread, and record the run's adjudication set (spec §4.A, D3).** Assemble the run's adjudication set from (1) the plan's red-team report `## Adjudications` rows (`docs/red-team/<plan-slug>.md`, machine-readable block) — the existing producer, now instructed on the /war side too — and (2) **every scope finding you adjudicate at this gate** — especially a known spec delta routed to a follow-up issue — recorded **at the moment of adjudication** as a preformatted string row naming the delta, the ruling, the route (`#<issue>` where filed), and the adjudication moment — and (3) **the Checkpoint's ask rulings**: each parked ask the operator rules at the strike-list ruling gate (`## Checkpoint`) is minted as an adjudication row there and accumulates into the set threaded to every subsequent phase. Thread the assembled set as **`args.adjudications`** (array|null) into **every** per-phase Workflow of the run; record each row in the run ledger (the `ledger.json` top-level `adjudications` key — [references/schemas.md](references/schemas.md)). Interactive runs present the rows at the approval gate alongside the DAG (next step); `--afk` self-adjudicates and records without waiting (the standing afk posture). No adjudications ⇒ omit the arg — every prompt stays byte-identical to today. **Provenance discipline:** a row records a real ruling made at a named moment — the Lead never synthesizes a row to smooth over an unruled delta (spec constraint 6) and a row is **never mined from arbitrary prose** — rows come only from the three producers above; a row re-scores a known, already-routed delta and never waives a gate, floor, or backstop (ADR 0017).
6. Present the DAG to the user as an issues preview **and any per-phase Workflow patches** you intend to inject. **Wait for approval/edits.**
7. On approval, run `bash ${CLAUDE_PLUGIN_ROOT}/skills/_shared/gh-preflight.sh "<overrides.ghUser>"` (the gh-account preflight — asserts the active `gh` account equals `overrides.ghUser`, switching + re-verifying on drift, failing loud on an unrecoverable mismatch; empty/unset `ghUser` ⇒ no-op exit 0) **before the file-epics batch**, then file **all phase epics up front** (labels `phase:N`, `status:todo`) so the full scope exists before any teammate launches. Run the same preflight again **before each per-phase sub-issue batch** and break that phase into **task sub-issues just-in-time** at its start (so later phases absorb learnings/drift). Record everything in the ledger.
8. **Submodule router (Increment 2).** After extracting the DAG, call `submodulePaths(repoDir)` (from `skills/_shared/provision.mjs`) to get the declared submodule paths from `.gitmodules` — when any task's target overlaps one, read [references/submodule-flows.md](references/submodule-flows.md) (§ Submodule router): task classification + paired gitlink-bump proposals (human-approved, explicit `target repo` tags), the base-branch resolution order, the `/red-team`-time reachability precondition, and the `--afk` un-owned-submodule refusal.

## Run manifest (telemetry)

A **fail-open bookkeeping record** the Lead accumulates as the run proceeds — a sibling of the run ledger, but **telemetry, not a correctness record**: it is **never** read on resume. `/war-review` consumes it post-run to render the run's cost/effort + friction report (the closing-handoff step — see `## Finish`). Full field reference: [references/schemas.md](references/schemas.md).

**Where.** `.claude/war/runs/<runId>.json` under the **main checkout** — resolve the anchor exactly as the survey manifest does (never the invoking worktree's own `.claude/`, which a per-worktree session would strand):
```bash
MAIN=$(dirname "$(git rev-parse --path-format=absolute --git-common-dir)")
# manifest: $MAIN/.claude/war/runs/<runId>.json
```
`runId` = `<plan-slug>-<YYYY-MM-DD>`; a same-run resume rewrites the file in place (**latest-wins per runId**). Untracked-ness **rides the existing `.claude/` exclude** the provisioning `ensure-exclude` step writes into the main checkout's git dir — **no `.gitignore` change**.

**Stamps — fail-open, never resume input.** Initialize at run start (top-level `runId`, `planPath`, `configProfile`, `startedAt`), stamp each phase at launch and on return, and stamp the run's `endedAt` at the end; every `startedAt`/`endedAt` is a real clock read at the stamped boundary, never a placeholder. Every write is **best-effort** — a failed write logs **one** line and the run proceeds unaffected; bookkeeping **never** blocks a run, and the manifest is **never** resume input (the resume ordering git > issue labels > `ledger.json`, [ADR 0008](../../docs/adr/0008-git-is-the-resume-source-of-truth.md), is untouched). When stamping a phase boundary — the exact per-stamp field set, the harness-surfaced `workflowRunId`/`transcriptDir` capture rule (the Workflow launch envelope, never the return object), and the binding MUST-carry list — read [references/run-manifest.md](references/run-manifest.md).

## Per phase (in DAG order)
**Prefetch prior lessons (spec §4.5; skipped when `memory.retrieval` is `false` or memory was disabled at Setup — those are the *only* skips).** The Lead may **not** elect to skip prefetch for its own context budget, time, or convenience: the query output is threaded into `args.memory` programmatically by the same step that assembles the rest of the phase args, so it **never needs to pass through the Lead's context**. (The fail-open clause below covers a genuine prefetch *failure* — a non-zero CLI exit — never a deliberate omission.) Immediately after this phase's just-in-time task decompose, in the same Lead Bash context, run **one batched** `node ${CLAUDE_PLUGIN_ROOT}/skills/_shared/war-memory.mjs query --queries <file> --local <local root>` (the `--queries <file>` format is JSONL — one `{"label":…,"text":…,"seat"?:…,"topK"?:…,"budget"?:…}` object per line; a plain-text line-per-query file is not JSONL and dies at the parse, #1408) (always pass `--local` — the Setup-resolved local root; the CLI never guesses a root from the cwd, so an un-flagged prefetch walks an empty corpus and logs nowhere; add `--repo <resolved repo root>` when the repo root resolved, so prefetch reads the repo's published lessons too — retrieval keeps failing open, and an absent repo root simply omits the flag) covering every prospective seat: per task, one worker query (`<task title> <plan slice> implementer pitfalls`) and one auditor query per roster seat (`<task title> <plan slice> <lens> <lens catalog line>`); one servitor query for the phase (all task titles + slices + "memory dedup capture"). The refiner gets none. Thread the emitted blocks into the Workflow as `args.memory` (`{ byTask: { <task-id>: { worker, seats: { <lens>: block } } }, servitor }`) — the template concatenates them like `intent`. **Retrieval fails open:** any prefetch failure ⇒ omit `args.memory` (empty ⇒ byte-identical prompts) + one ledger line `memory: prefetch failed (<reason>) — phase ran lesson-less`.

Run **one Workflow per phase** from [assets/workflow-template.js](assets/workflow-template.js) (dispatched via a run-scoped **staged copy** — see the staging step below), passing the approved phase DAG + config (incl. `learningsTarget`, `memoryLocalRoot`, `memory` from the prefetch above, **`agents` / `audit` / `run`** from the resolved run config, `overrides.ghUser` threaded as `args.ghUser` (default `''` — the gh-preflight no-op), and this phase's **resolved** `overrides.testPattern` — threaded into `args` like the resolved gate, so the template reads `plan.gate` / `plan.testPattern`) as the Workflow `args`. **Per-phase pending-proposal re-check:** when the ledger carries a pending rejected `testPattern` proposal (the `--afk` sanity floor's fallback note) and the value to thread is still `null`, read [references/setup.md](references/setup.md) (§ Per-phase pending-proposal re-check) before threading — adoption is monotonic and validator-gated there; otherwise thread the resolved value unchanged. **Stage the per-phase script first (ADR 0037 — per-phase dispatch identity).** Resolve the run's staged-scripts directory `$MAIN/.claude/war/runs/<runId>/` — the per-run directory **sibling of the run manifest** `<runId>.json` (same `runId` = `<plan-slug>-<YYYY-MM-DD>`), resolving `$MAIN` with the **same main-checkout anchor idiom the Run-manifest section documents** (no new anchor code); its untracked-ness **rides the existing `.claude/` `ensure-exclude`** the provisioning step writes — no `.gitignore` change. Then run the **landed** stager: `node ${CLAUDE_PLUGIN_ROOT}/skills/war/assets/stage-workflow.mjs ${CLAUDE_PLUGIN_ROOT}/skills/war/assets/workflow-template.js $MAIN/.claude/war/runs/<runId> <planSlug> <phase.id> [<campaignOrdinal>] [--force] [--args <file>]` — the `<campaignOrdinal>` comes from the `/war` invocation's `--campaign-ordinal <K>` **when present** (absent ⇒ omit it, and the `c<K>` basename segment is simply dropped; `/war` never scans campaign ledgers itself). It prints the staged **absolute path**; **dispatch that printed path as the Workflow `scriptPath`** — never `assets/workflow-template.js` directly. **Write-if-absent:** a same-run relaunch or a `resumeFromRunId` resume **reuses** the existing staged script byte-untouched (approved injected stages and journal-replay stability survive); a deliberate propagation of a shipped-template edit passes `--force`. **Over-size args ride the staged script (`--args <file>`).** At real campaign size the assembled phase args cannot ride the Workflow tool call — the measured class is ~104.5 KB (`args.memory` blocks + verbatim plan slices + the Commander's Intent). The Workflow:
- cuts `integration/phase-N` off the working branch;
- **Works** — fresh `war-worker` agents (one per task) in per-task worktrees off the integration tip, wave by wave (barrier between dependency waves);
- **Audits** — independent read-only `war-auditor` seats review the pinned SHA, one seat per entry in the task's **roster** (1–5 distinct-lens seats, each at its own depth). **Critical/Major block**; every **Minor/Nit routes by auditor-owned disposition** (ADR 0013) — `absorb` (mechanical + intent-consistent: fixed in-phase by the per-task ace, or by the phase-close sweep when `phaseClose:true` or the file is release-slot-adjacent), `follow-up` (a `war-followup` issue — the auditor must state why it is not absorbable), `note` (phase report + servitor feed, never an issue), or `ask` (a decision-shaped Minor/Nit only the operator can rule — mandatory `question` + `fork`; parks on the return's `asks[]` and is ruled at the Checkpoint strike-list gate, never filed unruled, never demoted by machinery); omitted → Minor becomes follow-up, Nit becomes note, `absorb` and `ask` are never defaulted; approval **unanimous on one SHA** (re-confirm when HEAD moves) — unanimity needs no odd parity, even seat counts are legal. A split → **one rebuttal round** → resolve or escalate. The default roster is the quartet (correctness / cascading-impact / plan-faithfulness / security) at `deep`; swap or add a domain lens (e.g. healthcare-safety) on flagged code;
- **Refines** — `war-refiner` rebases each approved task onto the integration tip, re-runs the gate, and merges **serially** (the queue). A gate/audit failure routes a batched `FIX_NEEDED` to a fresh fix-worker on the same worktree (≤ `round_limit=6`, then escalate `audit-blocked`);
  - **`--ace` (default on via `run.ace`; the economy preset pins it off).** With `run.ace`, an **approved** task with **zero blockers** and **≥ 1** `absorb`-disposition finding (legacy `autoFixable:true` reads as `absorb` for one release — deprecated) gets a pre-merge ace **batch** fix (one batch commit, on the shared `fixRounds` budget) + a panel **re-audit at the new SHA**. The per-task ace serves only non-`phaseClose` absorbs passing the **narrowed** release-slot backstop (`plugin.json`/`marketplace.json` refused — README and other shared files are no longer refused); `phaseClose:true` or a release-slot filename routes to the **phase-close queue** instead. If the re-audit re-approves, the polished tip merges; on regression the batch enters the bounded **ace bisection** ladder (canonical: `aceBisect` in `workflow-template.js`) — named culprits excised, the remainder re-applied as ONE subset (blind halving only on ambiguous attribution), subsets serial at the tip, depth ≤ 2, same-file findings never split; each subset commit charges one `fixRounds` slot, carries the deterministic `Ace-Subset:` trailer, and its dispatch preflights the bisection range for that trailer (never the tip alone — resume idempotency). Failed subset tips are **forward-reverted** (`git revert`, never `reset --hard`), only finally-failing subsets demote (plus the subsets still queued when the **floor-retry reserve** stops the ladder — logged, by design), salvaged subsets merge, and the **originally-approved work still lands** — ace **never** turns a mergeable task into a hold or escalate. **Budget-bounded re-entry (ADR 0013 amendment).** A fresh `absorb` born at ANY re-audit dispatches another ace-style batch on the same machinery (canonical: `aceReentry`) while `fixRounds < roundLimit − 2` — that **floor-retry reserve** is the SOLE bound, no new round type. Reserve-blocked or spent ⇒ `phaseClose: true` → sweep ⇒ sweep-discard ⇒ `follow-up`; a forward-reverted finding never re-enters; every demotion logged. **Durable-record rule (D3):** absorbed findings are recorded via the ace **commit message** (citing each finding's title + rationale) and the `aced` list in the phase report — **not** as GitHub issues. **Residual rule:** a failed or ineligible absorb **demotes one step** on the terminal-disposition ladder (→ `follow-up`, logged — per subset under bisection; with `--ace` off every absorb demotes this way, and a fileless absorb takes its severity default); only `follow-up`-routed findings file as `war-followup` — zero unrouted findings on every exit path, nothing drops silently.

- **Manifest stamp (telemetry, fail-open).** Before posting the phase report, complete the Run-manifest section's on-phase-return stamp (`endedAt`, dispatch counts, task terminal statuses, `land`, envelope aggregates); a skipped stamp is the "unfinalized phase record" friction row `/war-review` reports; fail-open discipline unchanged (a failed write logs one line and never blocks the advance).
- **Issue-lifecycle floor — gate the DAG advance (§4.1).** Before advancing the DAG past this phase, run `bash ${CLAUDE_PLUGIN_ROOT}/skills/war/assets/assert-issues-filed.sh assert <ledger.json> <phase-id>` (it runs `gh-preflight.sh` itself first, so an account flip cannot fake its exit). It confirms the ledger's `epic_issue` and every `tasks[].issue` exist on live `gh`, and — on a phase being **landed** — that the epic is `state:CLOSED` **and** carries `status:done`. **Route by exit code:** `0` ⇒ verified, advance; `1` ⇒ blocks the advance, surfacing the named route (`issues-missing` naming the missing/null issue, or `done-but-open`) — treat as an escalation to resolve before proceeding; `2` ⇒ a gh/network/ledger-parse **tooling error**, escalate as such, **never a silent pass** (exit 2 never collapses into 1). On a **landed** phase, close the epic via the floor's atomic mode — `bash ${CLAUDE_PLUGIN_ROOT}/skills/war/assets/assert-issues-filed.sh --close-epic <n> --sha <sha>` (one call does `+status:done` / `−status:in-progress` **and** `gh issue close --reason completed` with the landed-SHA comment) — **instead of** separate label/close commands, so `status:done` can never outlive an open epic.
- **Follow-up filing floor — gate the DAG advance (D4, #1331).** Before advancing the DAG past a handoff-emitting phase (`landed` / `held:escalation`), every `handoff.followUps[]` entry must carry a **non-null `issue`** — the Workflow's `file-followups` dispatch normally stamps them (**consolidation precedes filing**: the engine collapses duplicate rows into `seats[]`-corroborated candidates pre-dispatch and asserts the returned `clusters[]` manifest — canonical: `FOLLOWUP_FILING_RESULT` in `assets/workflow-template.js`); any null ⇒ file it **now**, inside the preflighted per-phase gh-write batch above, **under the same discipline** — one issue per root cause, an open `war-followup` match gets a **corroboration comment**, never a new issue — and stamp the number into the ledger's phase `handoff` record. **Never advance over a null `issue`.**
- **Ask ruling gate — the strike list, gate the DAG advance absolutely (#1550, ADR 0013 amendment).** When `handoff.asks[]` is non-empty, **one gate rules all parked asks in a single pass**: render the strike list — one row per ask, its `question` + `fork` (the decision needed and its two branches) + task/seat/sha provenance, plus, on a citation-matched row, its `citationPrefill` (the engine's matched standing row + match rationale + executed sha + recommended ruling, #1879): the operator confirms or overrules in one stroke — never auto-unparked past a present operator, and a confirm-via-prefill is recorded as a citation-informed ruling in the same telemetry channel as an `--afk` citation resolution (the aced record's citation stamp) — and put it to the operator with the phase report. The advance floor is **absolute**: never advance the DAG over an unruled ask — interactively this binds as a hard wait (the run does not proceed until every row carries a ruling; no severity, count, or staleness exception). **Ruled-ask execution (ADR 0013 amendment 2026-08-27):** a ruled ask whose fix is fully specified **executes in this run** — injected into the next phase's decompose as a small first-class task carrying the ruling and its `suggested_fix`, or, in the final phase, ONE bounded polish-style post-land dispatch at the working tip. **Ruled-ask filing parity** is now filing-on-non-execution: file an issue **only** on **cannot-execute** (no vehicle, cross-task, budget) or execution-failure (regression ⇒ revert), the ruling recorded in it either way — never silently, never as default litter; when filed, it files Lead-side inside the preflighted per-phase gh-write batch under the same discipline as engine-filed follow-ups — one issue per root cause carrying an `## Evidence artifacts` section, dedup-checked first against the engine-filed `handoff.followUps[]` rows and open `war-followup` issues (a match gets a corroboration comment, never a duplicate) — and mint each ruling as an adjudication row (the third producer, Decompose step 5) in **standing-row format** (today's ruling is tomorrow's `--afk` citation source), recorded in the ledger and threaded to every subsequent phase. Unruled asks are **never filed** — the engine already excludes them from consolidation and the file-followups dispatch; the Lead never re-adds one. **`--afk` posture:** a parked ask matching a standing adjudication row resolves by citation (the matched row quoted as the ruling) and may carry an **actionable absorb** outcome executed through the re-entry vehicle, its record carrying the matched **row-id + match rationale**; the row must cover the finding's NAMED trade-off, ambiguity is no-match; a no-match **demotes to follow-up with the question preserved** in the issue body — visibly not loss-free, flagged in the phase report; a suppression row is minted **only from an operator ruling, provenance-marked** — `--afk` never mints one.
- **Never-waive rule (§4.4 — Lead prose).** A validation that is in **none** of: the resolved gate, a deterministic floor (test / packaging / submodule), or the plan's backstop section (a plan-declared or Setup-auto-recorded deferred validation) **may not be waived in prose mid-run**. Do not narrate it away as "skipped" or "not applicable" in a phase report — **escalate to the operator** instead (interactively wait; under `--afk` this is a hard escalation, since only the operator can ratify a new waiver). This is the behavioral fix for the silent-prose-waiver failure the whole feature exists to prevent — a deferred validation is legitimate only once it is a ratified backstop, never as an ad-hoc mid-run sentence.
- **Fail-closed phase classification (§4.2 — apply on every phase notification, before any land/hold/advance decision).** On each phase Workflow notification, derive `landDecision` as follows:
  1. If `status !== "completed"` (the Workflow timed out, was killed, or returned a non-`completed` notification) → classify as `held:phase-incomplete`.
  2. Else if the result is missing, unparseable, or `landDecision` is not in the known set (`landed`, `held:escalation`, `held:nothing-merged`, `held:land-failed`, `held:phase-incomplete`, `held:workflow-error`, `held:submodule-pr`) → classify as `held:workflow-error`.
  3. Else → use `result.landDecision` as returned.
  Never skip this gate — a phase that failed to run must never silently advance the DAG.
- **Outcome handling (§4.3):** when the derived `landDecision` is any `held:*` hold — or a task returned `env-blocked`, a merge/land `gate_failed` arrives (with or without a `gate_failure_class`), or you complete a phase's land manually — read [references/resume-and-recovery.md](references/resume-and-recovery.md) (§ Checkpoint outcome handling) and follow the matching arm: terminal vs retryable holds, the `held:land-failed` root-cause recipes, the escalation-completion land, `env-blocked` evidence gating, `gate_failed` class routing, manual-land hygiene, the exactly-once learnings capture after a manual land, the Recovery-relaunch entry points, and the held-partial-phase recovery runbook.

## Finish
When all phases land, run `bash ${CLAUDE_PLUGIN_ROOT}/skills/_shared/gh-preflight.sh "<overrides.ghUser>"` **before opening the PR** (the Finish-PR gh-write site), then open **one PR** working → landing, body summarizing phases landed, learnings, escalations resolved, and follow-up issues filed. The body carries a mandatory **"Unexecuted backstops"** line (§4.4) — the union of every phase's `handoff.backstops[]` (plan-declared plus Setup-auto-recorded deferred validations), each rendered `check · why deferred · runner`, `source: 'auto'` entries flagged, and any **AI-declared** entry rendering its marker (never surfaced as operator-ratified); literal `None` when no phase deferred anything. This is the final land-time surface for every validation the run consciously left un-run. Report the PR URL. **Closing handoff:** point the operator at **`/war-review`** as the post-run step — it reads this run's manifest (`.claude/war/runs/<runId>.json`), renders the telemetry + friction report, and offers one confirmed friction issue.

## Invariants (never violate)
- The Lead never edits code — only decomposes, gates, surfaces escalations, talks to the human. Keep your own context lean: push detail into the ledger + issues, not your chat history.
- `war-auditor` is read-only (file tools plus a fail-closed guard restricting Bash to read-only git — `hooks/validate-auditor-git.sh`); `war-servitor` is the only reviewer-side role that writes, and only under the threaded absolute local memory root (repo-root publication is the Lead's Gate-2 promotion — the servitor never writes `docs/learnings/`) (confinement is the capability allowlist — no Bash, only Read/Grep/Glob/Write/Edit — so its sole write path is Write/Edit; the PreToolUse scope hook gates those by `agent_type` to the local memory path-pattern, and denies mutation of any pre-existing untagged memory file, [ADR 0002](../../docs/adr/0002-scope-by-agent-type.md)); workers stay inside their worktree (the hook confines a `war-worker` write to a dir bearing a `.war-task` marker); `war-refiner` owns **all** merges, one at a time, never `--force`/`reset --hard` on shared branches. The **one force exemption** (ADR 0012): a worker may `git push --force-with-lease` ONLY its own task branch, and ONLY after a dispatch-rebase diverged it from its pushed remote — never any other ref, never for any other reason. The **refiner**, not the worker, also owns worktree provisioning — it runs `provision-worktrees.sh` to cut the **plan-namespaced** integration branch and `git worktree add` each task ([ADR 0001](../../docs/adr/0001-explicitly-managed-worktrees.md), [ADR 0003](../../docs/adr/0003-plan-namespaced-branches.md)).
- Never merge a task with an open Critical/Major finding, without a passing gate, or before unanimous audit. Never merge un-audited. Never let a worker satisfy the gate by deleting/skipping tests. **Baseline carve-out (spec §8):** the "passing gate" clause admits exactly one exception — a `gate_failure_class:'baseline'` red (the same failure **proven pre-existing at the classification base**, its debt **recorded as a `source: 'auto'` backstop**) may proceed; an `introduced` red — or an unclassified/absent-class one, the permanent fail-safe — **never** does. (The delete/skip-tests prohibition is absolute and has no carve-out.)
- **The phase-close sweep is fail-open — it may only improve the tip.** It dispatches only when the phase would already land; a re-approved polish merges at the serial queue's tail, anything else **discards** and the pre-polish tip lands exactly as it would have (a discarded sweep recomputes nothing — never a hold). Discard leaves the polish branch + `p<N>-polish` worktree in place (never-lose-unmerged-commits; reaping is a human act) and demotes the queue to `follow-up`. Every demotion on the terminal-disposition ladder — ace bisection subsets included — is logged; nothing drops silently.
- When judging or authoring a revert of a phase-close polish commit, read [references/resume-and-recovery.md](references/resume-and-recovery.md) (§ Phase-close polish reverts — never self-justifying).
- **Deterministic test-floor** — the **refiner** runs `assert-test-in-diff.sh` at merge-task, pre-merge, for every task where `requiresTest:true`. This is a standing-instruction surface in `agents/war-refiner.md`, independent of the dispatched merge-task prompt threaded in `workflow-template.js` (memory `standing-instruction-vs-dispatched-prompt-coverage-split` — both surfaces must be kept in sync). A `no-test` result routes the bounded fix-worker + full re-audit sub-loop; the Lead never bypasses it.
- Models/effort come from the resolved run config (`/war-room`); **defaults** are `war-worker` = fable at session effort, fix = fable at session effort, `war-auditor` = opus on `high`, `war-refiner` = sonnet at session effort, `war-servitor` = sonnet on `high`. `audit.autoEscalate` (default on) still widens a lone-seat roster on a Critical/low-confidence finding — toward the seat's `widen` nomination when it is valid (a non-empty list of distinct, non-reserved lens names → those lenses at `deep`), else the default roster's lenses (the byte-identical quartet-union fallback) — a union that keeps the lone seat, never duplicates, caps at 5. Target < 3× single-agent cost.
- **Every landed phase captures learnings exactly once**, by whichever path landed it: the in-flow Wrap-up when the Workflow lands (`landDecision === 'landed'`), else a Lead-driven `war-servitor` pass after a manual land. Skip if `servitorResult` is already set.
- At every diagnosis moment with **no mechanical classifier** — live validation, resume anomalies, `held:*` adjudication, the Lead's own manual operations — run the **self-confound gate**: enumerate and rule out your own and concurrent actors' mutating actions before blaming a subsystem, and keep validation **single-path** over shared mutable state (never manual + automated bring-up back-to-back; re-provision before switching — the incident's root act). For merge/land gate reds the refiner's `gate_failure_class` base re-run **is** that action-provenance evidence — consume it, don't re-litigate it. No **hypothesis promotion** — a memory/lesson write, a `war-followup` issue, a fix plan or spec, a sub-agent fan-out — without primary evidence plus a stated falsifier; a hypothesis that must survive compaction is a labeled ledger/phase-report **hypothesis** note, never a memory lesson (the D8 valve: record or escalate, then proceed).
