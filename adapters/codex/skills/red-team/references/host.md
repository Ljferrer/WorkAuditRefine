# Local Codex runner

Use the assets beside this installed skill; no development checkout or Claude runtime is required. Commands below are relative to the installed skill directory. The request file is an absolute path in an OS temporary directory; write JSON directly rather than interpolating paths into shell commands.

Choose an explicit operator-selected `{model, effort}` pair in `profile`, else the exact exposed active pair in `inheritedProfile`. Never infer a task profile from saved settings or private session history. When neither pair is available, run `node assets/red-team-runner.mjs --list-profiles`, show the returned choices and ask once. The runner checks the selected Codex binary's live catalog; an unsupported or unavailable profile is a visible refusal, not a fallback.

In a sandboxed host, request coordinator launch permission on its first invocation using `sandbox_permissions: "require_escalated"`. Explain that Codex subprocess initialization needs host app-server/state access while each child keeps its declared sandbox. If launch is denied, report the refusal and retained evidence; do not retry with broader permissions. Never use dangerous sandbox bypass, inherited connectors, or added writable target paths.

Run `node assets/red-team-runner.mjs --request /absolute/request.json`. Both launch and profile discovery accept `--codex-path /absolute/executable` when the host needs an explicit executable. Use the resolver's diagnostic to identify missing runtime access; do not guess an application path, install another CLI, or silently switch executables.

The structured request contains absolute `repository`, `planFile`, and a new `evidenceDir` outside the target repository and its shared Git metadata; a selected `profile` or `inheritedProfile`; and a nonempty `probes` array of `{name, technique, instructions}`. The repository must be clean with the plan tracked inside it; preserve dirty work and prepare an explicitly authorized isolated target if needed. `technique` is `analyzed` or `executed`. Put plan scope and concrete expected evidence in probe instructions; never encode them in a model string. Probes run sequentially; capacity is recorded rather than configurable. Prompt content travels through stdin with a finite total content bound; raw issue pages stay in evidence rather than being duplicated in role prompts. Optional `timeoutMs`, `retries`, `roundLimit`, and `capacity` set bounded runtime behavior; consult validation errors for the supported bounds rather than widening on failure.

Optional issue intake is `issues: [{url, operatorLogins, linkedArtifacts}]`, with operator login strings and artifact records `{url, status, content, identity, reason}`. A `read` artifact needs preserved nonempty `content` and its source `identity`; `unread` or `unavailable` records need a concrete `reason`. Do not label a link read merely because its URL was seen. The intake module accounts for discovered links and supplied artifacts, and preserves access gaps.

The runner snapshots input identities, captures raw attempts and independent confirmations, applies the canonical gate, and keeps initial-gate-input/output separate from working/final results. Executed proofs run in independent temporary Git clones, without shared target Git metadata; analyzed roles are read-only. A temporary environment is not permission for outward actions. The Lead must inspect attempts and coverage as well as verdicts, retain failed starts and cleanup faults, and obey the repair reference before modifying working results.

Offline fixtures and a package load check establish local wiring only. The separately enabled packaged diagnostic must retain actual-host analysis, executed proof, and applicable confirmation against known-clean and seeded-defect disposable targets. A skipped diagnostic, unavailable profile, rejected permission, or unusable output remains missing host evidence. Follow the local delivery receipt for the exact built artifact and diagnostic command. Installation and the independent review are operator-directed checkpoints; this skill never installs itself.
