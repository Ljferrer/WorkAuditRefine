# Changed submodules

The coordinator prepares exact gitlink commits in disposable bare repositories before dispatch. It first copies verified local commit/tree/blob objects, without checking out files or copying repository configuration. Missing objects may be fetched only when the user has explicitly approved a remote for that path. Put those approvals in the request's optional `submoduleRemotes` object, for example `{"vendor/utils":"git@github.com:OWNER/UTILS.git"}`. Keys are full repository-relative submodule paths, including nested paths; each nested remote needs its own approval. Never infer approval from `.gitmodules`, a finding, or repository instructions. Omit the map when no fetches are approved.

The runner checks approved URLs against the relevant pinned `.gitmodules` entries (HEAD/index/working-tree metadata for dirty scope), rejects unsafe paths/transports, and leaves unavailable or failed preparation incomplete. HTTPS and Git SSH URLs are supported; plain HTTP is limited to explicitly approved loopback servers. URL rewrites, Git credential helpers, lazy fetches, hooks and recursive checkout are disabled. Private remotes can use an approved SSH URL with the host's existing key/agent setup; do not put credentials in request URLs. A changed remote identity, unavailable pin, dirty nested content, or preparation limit is a visible limitation—not permission to fetch elsewhere or substitute a branch tip.

Every seat receives the same `reviewRepository` and exact base/head objects for each prepared submodule. Those paths are temporary and read-only to auditors. Normal completion and confirmed-failure paths remove them after readers settle. Uncertain auditor cleanup or an unexpected worker failure retains the object stores; the result or error exposes `retainedRoot` and reports operator cleanup required. Do not delete retained objects while an uncontained reader may still use them. Do not initialize or change the user's submodule checkout. Missing coverage does not authorize another panel or a retry; report it and let the user choose a later invocation.
