## 1. Context — the gap / problem

All fourteen issues touch the findings pipeline in `skills/war/assets/workflow-template.js`: intake, the routing ladder, parked asks, the ace gate, the end-state check, the follow-up filing block, the late-fix pass and advisory polish (verified: the 14 reader summaries' `affectedFiles`, survey 2026-11-08). Each fix lands in that one file, so the phases are serial.

**A. The intake floors read "None needed." as a fix.** `blankText` is a trim check only (`const blankText = v => typeof v !== 'string' || !v.trim()`) (verified: `blankText` at 35aa4144). The intake floor (`const fix = !blankText(f.suggested_fix)` in `intakeFloor`) and the gate-audit floor pass use the same test, so a seat `note` whose `suggested_fix` is "None needed." is rerouted to `absorb`. In one run this burned two ace rounds on a comment reword and a five-seat re-audit of an empty diff (verified: issue #2378 (2026-10-17)). The same `blankText(f.suggested_fix)` read also sits in `dispositionOf`, the behavior arm of `intakeFloor`, `gateHardOf` and the split-panel `fixless` survivor filter (verified: `grep -n 'blankText(f.suggested_fix)'` at 35aa4144 — six sites).

**B. Notes and follow-up records lose or repeat data.**
- `normalizeSeat` pushes one note per empty-content finding per audit round with no content-key check (`notes.push({ ... demoteReason: 'intake:empty-content' })`) (verified: `normalizeSeat` at 35aa4144). A seat that re-raises the same finding across round 0, the rebuttal and each fix-round re-audit leaves up to seven identical notes, and the handoff `notes` projection renders each one (verified: issue #2133 (2026-09-07)). Nothing routes on notes.
- The pre-filing collapse in the file-followups block (`const collapsed = []` … `hit.merged.push({ seat, title, rationale })`) never copies the merged-away row's `drainCause` (verified: file-followups consolidation loop at 35aa4144). `demote()`'s corroboration arm already does (`if (hit && f.drainCause && !hit.drainCause) hit.drainCause = f.drainCause`) (verified: `demote` at 35aa4144). So the `drain cause:` filing cell and `handoff.followUps[].drainCause` drop the cause for a merged-away drain row, which is the common case (verified: issue #2244 (2026-09-08)).
- A filed `demote:absorb-regressed` follow-up is never checked against a later ace of the same finding. Nine issues (#2510–#2518) in one run and twelve in another were filed for findings that later ace rounds or the sweep fixed before land, and the operator closed them by hand (verified: issue #2530 (2026-10-30); issue #2655 (2026-11-08)). `demote()` checks `acedKeys` only at demote time (verified: the REGISTRY CONSULT in `demote` at 35aa4144). A reverted key never re-enters the ladder (the oscillation bound), so a later fix arrives under a reworded title or through the sweep, and an exact-key check cannot see it (verified: `demote` header comment at 35aa4144).

**C. Parked asks and ruled-ask records.**
- `askContentKey` is `task + question text (or title)` (verified: `askContentKey` at 35aa4144). The re-audit prompt does not show the seat the asks already parked for its task. Seats reword the question at each SHA, so one question was parked at five SHAs by one seat and two by another, with no corroborators recorded (verified: issue #2373 (2026-10-06)).
- In the ruled-ask provenance surface loop, `const coordinateLess = rows.find(r => r.coordinateLessName)` has no text guard. `ruledAskRowText` sets `coordinateLessName: '(untitled)'` on a `{}` record whose text is `''`, so the refusal names a record that added nothing to `evidenceText` while a sibling string row is the one that failed the own-token floor (verified: `ruledAskRowText` and the coordinate-less pre-check at 35aa4144; issue #2142 (2026-09-07)).

**D. The citation contract is not told to seats.** `citationOf` refuses a `citation.row` under `CITATION_MIN_LENGTH = 24`, a gloss-extended superset of a threaded row, and a substring that two threaded rows share (verified: `citationOf` at 35aa4144). The engine comment above `AUDIT_VERDICT` states this floor, but the seat-facing surfaces do not. The dispatched DISPOSITION WIDENINGS clause (3) says only "the `citation` field (`row` + one-line match `rationale`)". `skills/war/references/disposition-eligibility.md` item 3 says the same. `agents/war-auditor.md` has only the citation-soundness bullet (verified: all three at 35aa4144). A refused citation rides as a plain absorb, the parked ask loses its `citationPrefill`, and the seat sees only an engine log line (verified: issue #2224 (2026-09-08)).

**E. Gate evidence and the end-state check.**
- The endstate-check dispatch runs whenever `endStateCheckRows.length > 0`. Its header comment says "UNCONDITIONAL on merge outcomes" (verified: `LAND-BARRIER ENDSTATE-CHECK DISPATCH` block at 35aa4144). A phase whose tasks ran but none merged runs every check at the phase base. The end-state-only seat (`} else if (endStateClaims.length > 0)`) then attests rows unmet. In run df731486 a false AUDIT-TAMPER Major escalated the only task and the Lead landed by hand (verified: issue #2532 (2026-10-30)). The handoff already clamps this shape: `vacuousPhase = (tasks || []).length > 0 && landed.length === 0` makes every claimed row `unverified`. That clamp runs after both dispatches, and its note says "zero tasks ran", which is wrong when tasks ran but none merged (verified: `vacuousPhase` at 35aa4144; `landed.push` happens in `landMerged` at merge time).
- The endstate-check prompt's STATEMENT BOUNDARIES clause defines a boundary as a top-level unquoted `;` or newline, and says to append `printf 'cmd[%d] exit: %d\n' <i> $?` after each statement. It has no carve-out for the inside of a compound command (`for … do …; done`, `if`, `case`, `{ }`, `( )`), so a literal seat could insert a printf between `do` and `done` (verified: the ENDSTATE-CHECK DISPATCH prompt at 35aa4144; issue #2277 (2026-09-08)). The operator ruling of 2026-09-07 (#1782) fixed the printf derivation and is silent on compound commands (verified: issue #2277 (2026-09-08)). The reading-side twin is the `agents/war-auditor.md` execution rung 1 sentence "`;` or newline boundaries only", pinned by the "compound-check exit aggregation" REGISTRY row in `workflow-template.engine-1.test.mjs` (verified: at 35aa4144).
- The post-merge gate-audit seat for a task reads `gateLogPath: gateLogPathOf(m.gateLogPath) || GATE_LOG_UNTHREADED`, fed from `mr.gate_log_path` (verified: the `evItems` builder and the `mergedTasksForGateAudit.push` record at 35aa4144). `admitGateResult` silently sets `gate_log_path` to `undefined` when the returned path does not start with the capture prefix and end in `<6 chars>/gate.log`, with no log line (verified: `admitGateResult` at 35aa4144). The operator lists the "no captured gate log" row of #2329 as still open, seen again in phases 6 and 7 of a later run (verified: issue #2329 (2026-09-25), operator comment 2026-11-06).

**F. The ace gate and the absorb budget.**
- The segmented ace gate re-dispatch (`aceSegments`, bounded by `roundLimit`) runs only on the pair `gate_green: false` + `gate_segment: 'incomplete'` (`aceIsSegment`) (verified: `aceGateGreen` at 35aa4144). A reply with `gate_green: false`, no marker, no failing ids and no `head_sha` takes the RED arm and forward-reverts the ace tip. That is the reported "INCOMPLETE, not a failure" reply (verified: issue #2655 (2026-11-08); issue #2329 (2026-09-25), operator comment 2026-11-06 listing item 1 open). On a spent bound the gate takes the `died` route, which forward-reverts and sends the rows to the sweep (verified: `aceReaudit` comment at 35aa4144).
- The absorb-budget seed matches `absorbCharges` keys through `preMergedIdOf`, which only strips a `p<N>-` prefix. A barrier that keyed `{"1.1":0}` for task `t1-1` logs "NO usable absorbCharges entry" and seeds 0. On a relaunch that under-counts spent ace commits (verified: the absorb-budget seed loop at 35aa4144; issue #2373 (2026-10-06)). The 0-seed log does not print the keys the map did carry (verified: same loop).

**G. The late-fix pass residuals (#2661).** All verified in `lateFixPass` at 35aa4144 unless marked otherwise:
1. `let lateFixSeq = 0` is set on each launch, and `lfBranch = 'war/' + planSlug + '/' + id` carries no run id. A relaunch can reuse a spent branch name (the worktree path already carries `runId`).
2. The merge runs on `isSha(w.head_sha)` plus `allApprove`. The refiner's trailer check reads `${integration}..${lfBranch}`, and an empty range prints no line, so an empty late-fix branch fast-forwards as a no-op and is recorded `fixed`.
3. On `!ok` the loop sets `lfPrior` from `blockingOf(seats)` and continues. A seat `verdict: 'escalate'` loops like `request_changes`, and `escalateReasonOf` is never read, so the reason never reaches the hold or carry detail. The sweep panel has the same gap (`sweepApproved = allApprove(...)`, logged as `polish-rejected`).
4. A polish-panel `behavior` row with a blank fix or no file goes straight to `carryLate` on a non-final phase. It is never parked as an ask, which the intake floor's behavior arm does for the same shape ("behavior note with no fix on a named file → ask").
5. A behavior row from an unmerged task is now demoted (`demote:exclusion-set — origin task … did not merge`) before it reaches a round. This item is partly fixed (verified: issue #2661 (2026-11-08)).
6. The seeded-task mint (`tasks.push({ id, title: 'carried defect: ' … seed: s … })`) never reads `s.fixRounds`, though `carryLate` and the seed cap rule both stamp `fixRounds` on the carried row (verified: the seeded-task mint and `carryLate` at 35aa4144). The budget restarts each non-final phase.
7. The late-fix fence is `sweepExclude ∪ unmerged tasks' files ∪ RELEASE_SLOT_FILES`. A late fix charged to one task can edit a merged sibling's owned path, and the sibling then reads `NO_TASK_PROOF` in `task-integrated.sh` on a relaunch (fails safe) (verified: the `fence` const in `lateFixPass`; `no_proof()` in `skills/war/assets/task-integrated.sh` at 35aa4144).

**H. Advisory polish cross-file claim rule (#2578).** `POLISH_FILES_CLAUSE` limits ADVISORY POLISH sibling fixes to the task's own files and listed rows' files, and its comment says "A cross-file claim rule waits for its own plan and red-team (#2578)" (verified: `POLISH_FILES_CLAUSE` at 35aa4144). The operator ruling on PR #2577: "a task may claim files outside its set if no other task in its wave claims them, otherwise remaining sibling fixes go to the terminal polish task; not for zero-in. Follow-ups: first commit wins (later clashing rows go to the phase-close sweep), row target is the phase-close sweep queue" (verified: issue #2578 (2026-11-03)). The hazard that held the rule back: a clashing polish commit is forward-reverted (`registerRangeRevert`), and the merge-slot rebase replays both the commit and its revert onto a tip that already holds the winner's fix. That risks a `conflict` hold or undoing the winner's merged fix (verified: issue #2578 (2026-11-03); `registerRangeRevert` at 35aa4144). The one live data point (plugin 0.21.35) needed no wider rule (verified: issue #2578 comment). `skills/zero-in/SKILL.md` carries no polish prose (verified: `grep -i polish skills/zero-in/SKILL.md` empty at 35aa4144).

## 2. Pivotal constraints

- One owner of `skills/war/assets/workflow-template.js` per phase. Every phase is serial on it (verified: CLAUDE.md § The pipeline is gospel, code-boundary rule 1).
- Both-surfaces rule. A change to a dispatched auditor or refiner prompt lands with its `agents/*.md` card, or the card's referenced `references/` home, in the same commit, with a REGISTRY row and a no-slack `REGISTRY.length` floor bump (verified: CLAUDE.md § Execution architecture; the `REGISTRY.length >= 40` floor in `workflow-template.engine-1.test.mjs` at 35aa4144).
- No enum change. No new `HARD_ESCALATION_REASONS` or `KNOWN_LAND_DECISIONS` member is needed (verified: §3 resolutions reuse existing reasons). If a phase finds it needs one, it changes `land-decision.mjs`, the mirror in `workflow-template.js` and the drift guard in one commit.
- Never drop a finding silently (ADR 0013 ladder; operator ruling #2379). Every reconcile or dedup keeps the row in `notes` or as a count, and logs.
- An `ask` is never demoted (verified: ASK REFUSAL in the `demote` header at 35aa4144).
- Never force-push and never `git reset --hard` a shared branch (verified: `agents/war-refiner.md` forbidden list at 35aa4144). This bounds the #2578 design.
- `agents/war-auditor.md` hard cap 28,672 B; it measures 27,053 B at 35aa4144 (verified: `prompt-surface-budgets.test.mjs` and `wc -c`). The guard spec lands card bytes first, so headroom must be re-measured at each phase base.
- New test files follow the harness header and `runForm` rules (verified: `workflow-template.test-harness.mjs` header at 35aa4144). This spec adds tests to existing part files only.

## 4. Mechanics

Five serial phases, one `workflow-template.js` owner each. In each phase the engine task owns the engine file and the card or reference twins its prompt change needs. Test tasks own one test file each, carry `deps` on the engine task, and are file-disjoint from each other.

### Phase 1 — Intake, records and the citation contract (#2378, #2133, #2244, #2142, #2224, #2373 item 3)

- **T1.1 engine + auditor surfaces.** Files: `skills/war/assets/workflow-template.js`, `agents/war-auditor.md`, `skills/war/references/disposition-eligibility.md`. Implements D1 (`noFixText`, six sites, card no-fix sentence), D2, D3, D6, D7 (one commit, three surfaces), D5 (parked-ask thread in `auditPrompt` + card sentence). Sweep step: grep `suggested_fix` in `workflow-template.js` and handle every `blankText` or truthiness read of it.
  Manual same-scope survey required: after the grep, hand-scan the target file's same-scope tests and comments for same-meaning siblings worded differently, and list each straggler as a survey-derived correction.
  Measure `wc -c agents/war-auditor.md` before and after and record both in the commit body.
- **T1.2 tests, `deps: [T1.1]`.** File: `skills/war/assets/workflow-template.engine-1.test.mjs`. Fixtures: a `note` with "None needed." stays a note at the intake floor and at the gate-audit floor pass (one arm each); a sentinel Major reads fix-less at `gateHardOf`; the same empty-content finding over three rounds yields one note with `rounds: 3`; a merged-away drain row's `drainCause` reaches the `drain cause:` cell and `handoff.followUps[].drainCause`; a `{}` ruled-ask row beside a failing string row gets the generic own-token message; a re-audit prompt for a task with a parked ask carries its question verbatim; a REGISTRY row for the citation sentence over the card, the dispatched clause and `disposition-eligibility.md`, plus the `REGISTRY.length` bump; a REGISTRY row for the parked-ask sentence (card ↔ `auditPrompt`). Each new guard is proven red by deleting its engine line once before commit (verified: lesson `fix-the-finding-class-not-the-site-and-prove-every-new-guard-red-before-commit` in docs/learnings).

## 6. New domain terms (GLOSSARY.md)

- **No-fix sentinel** — a `suggested_fix` text such as "None needed." that names no fix; the floors read it as blank (D1).
- **Reconciled follow-up** — a `demote:absorb-regressed` row that a later ace fixed before land; it moves to `notes` and is never filed (D4).
- **Polish claim** — the first same-wave polish commit to touch a file outside every wave task's `files` owns that file for the wave (D19).
- **Net-zero clash range** — the commits after a task's approved sha that are exactly a clashing polish commit and its forward-revert, with the same tree as the approved sha (D19).

The terms land with doc-truth, which owns `GLOSSARY.md` after model-routing frees byte headroom [assumed: doc-truth adds them — if wrong: they go in this spec's Phase 5 diff within the hard budget].
