## 2. Pivotal constraints

1. Both-surfaces rule. A change to a dispatched refiner or worker prompt lands with its `agents/*.md` twin in the same commit (verified: CLAUDE.md § Execution architecture at 35aa4144).
2. One `workflow-template.js` owner per phase. Parallel tasks are file-disjoint. A test file that pins an engine change is a separate task with `deps` on the engine task.
3. Refiner card headroom is 23 B. Any refiner-card growth must be funded first: either a byte-identical ADR 0042 eviction, or a `Budget-Raise: ADR-0042` trailer (verified: `prompt-surface-budgets.test.mjs` at 35aa4144).
4. No new `KNOWN_LAND_DECISIONS` or `HARD_ESCALATION_REASONS` member. Every fix reuses `pin-transfer:unverified`, `env-died`, `landed` or `held:workflow-error` [assumed: no new enum is needed — if wrong: the phase that needs one also edits `land-decision.mjs`, the inline mirror and the drift-guard test in one commit].
5. Git is truth (ADR 0008). A refiner `landed` after an `ls-remote` confirm must still pass the engine's Git confirmation of land results (verified: the "An enum is a report, not Git evidence" comment above the merge confirmation at 35aa4144).
6. The preMerged block must keep `lastLandedTip` unset, so the handoff `tipSha` fallback is unchanged (verified: issue #2575 (2026-11-02)).
7. `schemas.md` rows for new optional fields are left to the doc-truth spec (verified: group contentionNotes). This spec names each field in §8 so that spec can describe it.
8. The `land-advance` script and its tests (#1837) stay with `shell-floors-tests-and-lint`. The #2657 fix is prompt-side only (verified: group contentionNotes).
