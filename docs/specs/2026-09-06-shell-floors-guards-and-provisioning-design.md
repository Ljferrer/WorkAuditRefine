## 1. Context — the gap / problem

**The auditor git guard has one real bypass and a contract that is learned by denial.** A command whose only residue is a newline is stripped to empty by the `$(...)` at the residue assignment, so `git diff HEAD<newline>echo pwned` passes the character check, matches the `diff` arm, and is allowed — a full read-only sandbox escape (verified: issue #1828 (2026-08-27); reproduced at `59e33f3`: piping `{"tool_input":{"command":"git diff HEAD\necho pwned"},"agent_type":"war-auditor"}` into `hooks/validate-auditor-git.sh` exits 0 while the `&&` control exits 2). The guard header still says "newline is implicitly denied because it is NOT in the allowlist", and the test file's Group M header still lists newline among the handled chain operators — both false (verified: issue #1830 (2026-08-27); `hooks/validate-auditor-git.sh` header NOTE and `hooks/validate-auditor-git.test.sh` Group M comment at `59e33f3`). The deny-message classifier is binary (chain-operator vs metacharacter), so `>`, `>>`, `<`, `(`, `)`, `{`, `}` and a lone backslash continuation all get the glob/alternation text with a Grep-tool remedy that does not describe the mistake (verified: issue #1829 (2026-08-27); the two-arm `nonchain_residue` branch at `59e33f3`). Field measurements: 122 denials in one run (~2.5 per seat), 64% of them quote-only; 186 in an earlier run; ~66 per plan run in the 2026-09-03 r4 run with backslash continuations the dominant miss at ~20 per phase (verified: issues #1915 (2026-08-28), #1421 (2026-08-15), #2001 (2026-09-03)). The auditor card and the dispatched prompt already carry the one-bare-git-command rule byte-for-byte, so #2001's card-omission hypothesis is false; the live gap is that neither surface names `\`-continuations, `#` comments or `&` explicitly, and no deny text echoes a corrected form (verified: `agents/war-auditor.md` § Read-only git guard contract and `skills/war/assets/workflow-template.js` `READ-ONLY GIT GUARD CONTRACT` prompt line at `59e33f3`). The card sits at 27,915 B against a 28,672 B hard ceiling — 757 B of headroom (verified: `agents/war-auditor.md` byte count and `FILE_BUDGETS['agents/war-auditor.md']` in `skills/war/assets/prompt-surface-budgets.test.mjs` at `59e33f3`). #1421's other two items (the leading-star test-floor prose and the `--close-epic` degradation) are already fixed in the tree; only its denial-volume item remains open (verified: issue #1421 reader summary (2026-08-15); `skills/war/SKILL.md` leading-star sentence and `assert-issues-filed.sh` `unknown flag: --reason` arm at `59e33f3`).

**Provisioning has a SIGPIPE false negative that can phantom-dirty a live checkout.** `branch_checked_out_anywhere()` is still `git worktree list --porcelain | grep -Fxq` under `set -euo pipefail`, while the sibling `branch_holder_path()` directly below it already uses the draining-awk idiom (verified: issue #1840 (2026-08-27); both helpers in `skills/war/assets/provision-worktrees.sh` at `59e33f3`). A worktree registry over the pipe buffer makes grep exit early, git dies of SIGPIPE, the helper returns 141 = "not checked out anywhere", and `cmd_sync_follower`'s guard then lets `git update-ref` move a branch that is checked out (verified: issue #1840 (2026-08-27)). The recorded lesson is exactly this propagation gap, and #2007 graduates it into a lint over pipefail scripts (verified: issue #2007 (2026-09-03); `docs/learnings/sigpipe-safe-drain-awk-idiom-fix-does-not-propagate-to-sibling-helpers-sharing-the-same-early-exit-pipeline.md` present at `59e33f3`). The live early-exit `| grep -q` sites in pipefail-declaring non-test scripts are the four in `provision-worktrees.sh` (`branch_checked_out_anywhere`, the `OWNED_REFS` membership check, the `not fully merged` classifier, and the `[rejected]` push classifier) — `assert-budget-raise-cited.sh`'s two `grep -Eq` sites named in #2007 sit under `set -u` only, no `pipefail`, so they are not in the hazard class (verified: grep over pipefail-declaring `hooks/*.sh` and `skills/**/*.sh` at `59e33f3`; `assert-budget-raise-cited.sh` `set -u` at `59e33f3`).

## 2. Pivotal constraints

- This spec's plan builds on master AFTER PR #2065 lands; Phase 7 assumes the `collectBlocks` (plural, whole-document union) shape and its documented "Code-fence blindness" ceiling (verified: issue #2090 (2026-09-06) on the PR #2065 branch). Every other construct is verified on master at `59e33f3`.
- Guard confinement is capability-first and fail-closed (ADR 0002). Phase 1 narrows (newline denies); Phase 3 widens (a balanced-quote-only residue is admitted once the verb is allowlisted). Each decision change is its own phase and never rides a message-only diff (verified: issue #1828 (2026-08-27)). `fetch` stays excluded; `git grep` stays denied; chain operators stay denied.
- Floor scripts exit 0/1/2: 1 = the named route, 2 = git or tooling error that never collapses into the floor status. Every floor change here keeps that contract.
- Standing card vs dispatched prompt: any auditor-contract or refiner-capture change edits `agents/*.md` and the `workflow-template.js` prompt build in the same commit, and its both-surfaces registry row in `workflow-template.test.mjs` moves with it (verified: `auditor-teach.md` § Guard-contract mirror architecture and the `both-surfaces (D20, #1381)` test at `59e33f3`).
- `agents/war-auditor.md` has 757 B of hard-ceiling headroom; a card edit that cannot fit routes through the `Budget-Raise:` trailer floor (ADR 0048), never a silent raise (verified: byte count and `FILE_BUDGETS` row at `59e33f3`).
- Parallel tasks are file-disjoint; `hooks/validate-auditor-git.sh`, `skills/war/assets/provision-worktrees.sh`, `skills/war/assets/assert-args-complete.mjs` and `skills/war/assets/workflow-template.js` each have exactly one owning task per phase. Shell tests stay bash-3.2-safe and cwd-independent.
- Default-flip rule: Phase 3 removes "quotes" from the forbidden enumeration on three surfaces; its gate asserts the OLD wording absent on all three.
- `workflow-template.js` is also owned by the engine sibling spec; the roadmap's contention table orders this spec's three one-task template touches after that plan's template phases [assumed: this spec's plan lands after the engine plan — if wrong: the three prompt-mirror tasks rebase onto whichever tip is live; they are prose-line edits with no engine-logic overlap].
