## 1. Context — the gap / problem

This group is the guard family under `hooks/`, plus the prompt sentences that teach agents what the guards admit. It has four parts.

**A. The auditor git guard is still learned by denial.** Auditor seats hit `hooks/validate-auditor-git.sh` many times per run. The counts were 122 denials (about 2.5 per seat) (verified: issue #1915 (2026-08-28)). Then 224 denials over 60 seats (verified: issue #1950 (2026-08-30)). Then about 66 per plan run (verified: issue #2001 (2026-09-03)). Then 21 over 24 dispatches (verified: issue #2372 (2026-10-05)). One run had 603 denials, 522 of them "forbidden character(s)" (verified: issue #2554 (2026-10-31)). The quoted-value admission halved the rate to 0.55 per seat, but it did not stop the denials (verified: issue #1915 (2026-08-28), operator comment 2026-10-31). The guard admits one quoted value after `-S`, `-G`, `-L`, `--grep=`, `--format=` and `--pretty=`, or as a whole token (verified: `mask_quoted_values` in `hooks/validate-auditor-git.sh` at 35aa4144). A probe at 35aa4144 ran the guard on the shapes the reports name (verified: probe of `hooks/validate-auditor-git.sh` at 35aa4144):

The residue classifier is binary. It deletes `&;|\n` from the residue. Any byte left over takes the metacharacter message, which talks about glob/alternation and the Grep tool (verified: `nonchain_residue` in `hooks/validate-auditor-git.sh` at 35aa4144). A redirect, a brace or a bare backslash gets a remedy that does not fit. It also loses the "one bare command" remedy, which now lives only on the chain branch (verified: issue #1829 (2026-08-27)). The `git grep` rule admits one shape: `-F` plus exactly one `-e <token>`, optional `-n -i -l -w -c`, one revision and `-- <pathspec>` (verified: `grep_deny` in `hooks/validate-auditor-git.sh` at 35aa4144). This rule is now the largest remaining denial class: 38 of 58 denials in one recurrence (verified: issue #2627 (2026-11-05), recurrence comment). The operator ruled that the "not a git command" denial stays on purpose, and that #1915 carries the live count (verified: issue #2556 (2026-10-31), ruling recorded from closed #2162). The operator also ruled that #2374 closes only once search-class denials stop in the most recent phases (verified: issue #2374 (2026-10-06), operator comment 2026-10-31).

The card and the dispatched prompt already teach the one-bare-command shape and the quoted forms (verified: `## Read-only git guard contract` in `agents/war-auditor.md` and the `READ-ONLY GIT GUARD CONTRACT` line in `auditPrompt` in `skills/war/assets/workflow-template.js` at 35aa4144). Card wording alone did not move the rate: two later runs on 0.21.15 kept about one denial per seat (verified: issue #2001 (2026-09-03), comments 2026-09-29 and 2026-10-20). `/war-review` already counts guard denials from transcripts as a friction signal. **B. Workers write files through Bash, and a denial splits a phase.** The worker card never says which tool changes a file (verified: `agents/war-worker.md` at 35aa4144, no Edit/Write rule). The scope hook and the lint hook match only `Write|Edit|NotebookEdit`. The app's host hook treats that folder as shared and denies every worker, ace, polish and endstate-check Edit/Write. The counts were 56, 31 and 29 denials across three runs (verified: issue #2351 (2026-09-29)). The same split hits the run directory. **C. Windows paths break every servitor memory write.** On Git Bash the servitor's `file_path` arrives as a drive-letter backslash path (`C:\<home>\...`), while `$HOME` is the MSYS form (`/c/<home>`). The `$HOME`-anchored case glob never matches, so every memory write is denied. One run captured 0 lessons in 7 phases (verified: issue #2644 (2026-11-06)). No hook normalizes a path (verified: `*war-servitor)` arm of `validate-worktree-scope.sh` at 35aa4144; no `cygpath` hit under `hooks/`). The provenance classifier and the memory-query `local` fence use the same raw `*/.claude/projects/*/memory` glob (verified: the classifier `case` in `hooks/validate-servitor-provenance.sh` and `memory_fence` in `validate-evidence-auditor-mcp.sh` at 35aa4144). If only the scope hook were fixed, the provenance hook would still miss a backslash path and let it through with no provenance check. It exits 0 on any path outside its glob (verified: `*) exit 0` after the classifier in `validate-servitor-provenance.sh` at 35aa4144).

## 2. Pivotal constraints

1. Capability-first confinement stays (ADR 0002). No change here widens what an auditor may write or which verbs it may run. Widening the `git grep` form changes argument shapes only, and `-O`, `-f`, `--no-index` and `--recurse-submodules` stay denied (verified: `grep_deny` text at 35aa4144).
2. The "not a git command" denial stays (operator ruling, issue #2556). The lever for non-git calls is prompt order, not admission.
3. Both-surfaces rule: every auditor, refiner or worker prompt change in `workflow-template.js` lands with its `agents/*.md` card in the same commit (CLAUDE.md "Prompt surfaces are split").
4. `workflow-template.js` has one owner per phase.
5. Card budgets are hard lines. A card that must grow past its hard line first evicts tier-2 prose byte-identically to a `references/` file with a trigger pointer (ADR 0042). A budget raise is not used here [assumed: eviction is cheaper than a cited raise — if wrong: a `Budget-Raise:` trailer citing ADR 0042 replaces the eviction].
6. Ordering: the worker stop-on-denial rule (D9) must not land before the placement rule (D12). Otherwise every worker in a desktop worktree session blocks instead of falling back to Bash. Both land in the same phase.
7. Hooks stay bash-3.2 safe: no associative arrays and no `${,,}` (verified: CONSTRAINTS header in `validate-auditor-git.sh` at 35aa4144).
8. A git command named in a hook test row must be one that git itself accepts (verified: `git_runs` comment, operator ruling recorded in `audit-tree-fingerprint.test.sh` at 35aa4144).

## 4. Mechanics

**Phase 1 — Guards (four parallel, file-disjoint tasks).**

- **Task 1.1 — auditor git guard.** Owns `hooks/validate-auditor-git.sh`, `hooks/validate-auditor-git.test.sh` and `docs/adr/0029-capture-grounds-on-committed-tip.md` (amendment). Implements D1–D5. Every probe row in §1's table becomes a test row with its new expected result. Add a row for each new deny message class. Add negative controls: `-O`, `-f`, `--no-index`, `-P`, a bare `-e` value that is a second revision, and a quote that opens mid-word stay denied. The deny-string couplings the test pins (group P and the branch loop's two flag groups) are reshaped together. Sweep step: grep `git grep admits one form only` and `exactly one -e` in `hooks/`, `agents/`, `skills/` and `docs/adr/`, and handle every match.
  Manual same-scope survey required: after the grep, hand-scan the target file's same-scope tests and comments for same-meaning siblings worded differently, and list each straggler as a survey-derived correction.
  Matches outside this task's files (the card, the dispatched prompt) are listed in the task's commit body for Task 2.1.

## 6. New domain terms (GLOSSARY.md)

- **Run root** — the checkout whose `.claude/war/` holds a run's worktrees, staged scripts, args files and manifest. It is `$MAIN` for a launch from the main checkout, and the launch checkout for a launch from a linked worktree (D12).
- **Denial class** — one of the auditor git guard's named deny groups (chain, grouping, metacharacter, grep form, branch read form, not-git), used by `/war-review` to report the per-seat rate (D1, D7).

## 7. Recommended ADRs

- **ADR 0029 amendment** — widen the admitted `git grep` form (D3): several `-e`, context flags and `-E`. Record which flags stay denied and why (`-O` runs a pager command, `-f` reads a file, `--no-index` leaves the repo).
- **New ADR (next free number)** — the run root follows the launch checkout in a linked-worktree launch (D12). It changes where `/war-review` and resume look for a run [assumed: this counts as a binding decision — if wrong: a `run-manifest.md` section is enough].

## 8. Open risks / implementation notes
