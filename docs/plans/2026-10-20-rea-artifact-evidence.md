## Pivotal constraints

- Default off is byte-identical: with `run.evidence` absent every prompt, roster and floor is unchanged.
- WAR never depends on REA. Presence is resolved by the Lead before launch (the MCP registry probe, or `rea doctor --json` in a non-interactive shell) and threaded as an arg; the Workflow sandbox cannot shell out and never scans a plan for the block (the Lead threads `args.targetArtifacts` from `target-artifacts.mjs` output).
- Confinement stays capability-first (ADR 0002): `war-auditor`, `war-servitor` and `war-refiner` never gain an MCP tool.
- Intent is never REA-invented (ADR 0013): REA settles facts, never Purpose, Method or End states.
- Target content never enters a plan, a prompt, a verdict, an issue body or a lesson. Bundles live only under the excluded `.claude/war/evidence/`.
- Doctrine lands cold (ADR 0042): one references home, pointers on the hot surfaces, no mirror. Every restated machine fact is guarded by extraction plus equality or de-mirrored (ADR 0025 rule 8). A surface may carry the `**Target artifacts**` marker value or the manifest path value only where the T1.7 doc-token guard lists it; every other surface names the constant.
- Five near-full surfaces are byte-funded: `agents/war-auditor.md` (untouched), `agents/war-refiner.md` (untouched), `agents/war-worker.md` (pointer ≤ 300 B of 492 B hard margin), `skills/war/SKILL.md` (pointer ≤ 200 B plus the PIN-16 sentence swap, together ≤ 300 B of 406 B), `CONTEXT.md` (glossary plus the widen de-mirror ≤ 700 B of 768 B). All three edited surfaces already sit above advisory, so their budget test WARNs; that is expected, not a defect. Re-measure with `wc -c` before every fix-round commit; never trust plan arithmetic.
- The template's prompt-literal share budget (hard 172,032 B, advisory 151,552 B) is the tighter line for Task 2.3; the stripped-copy floor is the second.
- The `workflow-template.js` edits of one phase are one task (same file → same task).
- Gate: the declared base is `node --test 'skills/**/*.test.mjs'` (CLAUDE.md's JS test command), resolved through the self-discovery gate (`resolveGate` in `war-config.mjs`, which appends the `*.test.sh` discovery loop). Pin it as `overrides.gate` via `/war-room` before launch; `overrides.gate` is `null` today and the repo carries no `package.json`.
- Done-when commands prove by a decisive token plus exit status: whole-suite runs use node's own exit (`node --test <file> && echo TOKEN`); titled-test checks use `--test-reporter=tap` with an awk pattern anchored `^…$` on the exact title.
- Release is its own trailing phase: four slots plus the `CHANGELOG.md` lead entry move together to the next free patch above the live base, proven against the working branch's merge-base (the 2026-09-11 Task 3.1 shape), never against `origin/master` and never with a network fetch.

## New domain terms · Recommended ADRs

- **Artifact evidence** — a plan claim whose evidence is a REA Evidence record bound to a target digest. The tag grammar lives in `artifact-evidence.md`.
- **Target artifacts block** — the Part 1 rows that turn the artifact recon lane on. Marker and fields per `target-artifacts.mjs` (`TARGET_ARTIFACTS_MARKER`, the row shape).
- **Evidence seat** — the roster row whose `agentType` is the evidence member of `SEAT_AGENT_TYPES`, carrying the `EVIDENCE_LENS` lens (`war-config.mjs`).
- **Digest manifest** — the payload-free manifest a worker commits at the path `MANIFEST_PATH_TEMPLATE` names.
- ADR 0053 (new): REA artifact evidence as an opt-in source class (passes the triad: a tag grammar is hard to reverse, surprising without context, and trades confinement against measurement). It names the MCP matrix by agent type only and points at the evidence-auditor MCP hook, by role, as the owner of the allow and deny sets.
- ADR 0041 amendment row: for the evidence seat only, the REA-reported subject sha256 matched against the manifest at `audit_sha` is rung 1.

## Commander's Intent

- **Purpose:** a plan can rest on what a shipped binary or app actually does, not only on source, and WAR proves and audits those claims the same way it proves source claims.
- **Method:** extend the D4 evidence tag to REA artifacts behind a plan-side artifact declaration and a run-side `run.evidence` knob. War-strategy gains an artifact recon lane, red-team a replay probe, workers a gated dispatched clause, and audits a new evidence seat that measures for itself. Target content never enters a plan or a prompt. Everything is off by default and fails open when REA is absent.
- **Mechanism latitude:** the lint regex shape · the manifest layout beyond the named digest keys · the new MCP hook's internals inside its fail-closed, suffix-keyed, canary-checked contract · the `**Target artifacts**` parser's code shape · the dispatched clause wording beyond its two pinned tokens (the manifest path and `get_evidence_bundle detail=summary`) · the card pointer's trigger words inside the ADR 0042 `when <trigger>, read references/<file>` shape · the exact REA tool names in the allowlist, derived from the effect predicate at the REA version measured at land. Substituting any of these mechanisms while the End states and binding guardrails hold is not a plan deviation and warrants no issue.
- **Binding guardrails:**
  - G1 · PIN-1 ‡: the evidence seat is offered only with `run.evidence` on and REA present, and `validate()` rejects an evidence-type roster row while the knob is off. Presence means the MCP registry carries `mcp__rea__binary_session`, or `rea doctor --json` in a non-interactive shell reports the needed providers ok. The Lead resolves it before launch and threads it as an arg; the engine never probes and never scans plan text.
  - G2 · PIN-5 ‡ cite-only: no target content in any plan, prompt, verdict, issue body or lesson. Bundles live only under `$MAIN/.claude/war/evidence/<plan-slug>/`, written after `provision-worktrees.sh ensure-exclude $MAIN` has run.
  - G3 · Off by default. Every prompt is byte-identical when off. With REA absent the run proceeds, logs one loud line, and seats no evidence auditor.
  - G4 · PIN-11 MCP matrix: `war-auditor`, `war-servitor` and `war-refiner` reach no REA tool. `war-evidence-auditor` and `war-worker` reach only tools that pass the effect predicate: never `mutatesTarget`, `executesForeignCode`, `mutatesDevice` or `destructive`. The hook owns the allowlist literal as full `mcp__rea__<tool>` names; the card's `tools:` REA entries are guarded set-equal to it and the presence-check tool is guarded as a member. The matcher strips any server prefix and compares the tool suffix, fails closed, and carries a live-name canary.
  - G5 · Cite-only is enforced by the advisory lint and the red-team `untrusted-content` probe. It is never a merge floor and never a hard `/war` gate.
  - G6 · A manifest carries only the digest keys `MANIFEST_KEYS` exports (`evidence_id`, target `sha256`, `provider`, `tool`, `parameters`, `limitations`); `artifact-evidence.md`'s `Manifest keys: ` line is the doc home, guarded by Task 1.7.
