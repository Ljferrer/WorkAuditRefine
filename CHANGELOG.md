## 0.21.1 — 2026-08-29
**0.21.1** — Reply Standard hooks (by [@kem_glitch](https://www.instagram.com/kem_glitch) on Instagram): the plugin now ships the Reply Standard hook pair, copied byte-for-byte from the author's distribution into `hooks/reply-standard/` and registered in `hooks/hooks.json` under `python3`. `card.py` (`UserPromptSubmit`) prints a deterministic reply-standard card beside each operator prompt — the whole card for a prompt that looks like a question or runs over 12 words, one line at six words or fewer, the Shape half between — and opens by naming the previous reply's violations when `meter.log` carries any; `meter.py` (`Stop`) scores the turn's final reply (`last_assistant_message`) with the SimpleEnglish STE counters plus two house counts (American spelling, dashes) and appends one JSON row to `meter.log` beside the script, never blocking and printing nothing. Reach: both events fire in the main conversation only — a WAR phase's workers, auditors, refiners, and servitors run as subagents, where `UserPromptSubmit` does not fire and turn-end is `SubagentStop`, not `Stop` — so no WAR phase behavior changes. The pair is toggleable via the WAR run config: a new validated `hooks.replyStandard` key (`war-config.mjs` DEFAULTS + validation, default `true`, on the `/war-room` override list) is read fail-open by a thin `gate.py` wrapper in front of the byte-for-byte scripts — only an explicit `false` disables. Beyond the hook registrations, the `hooks/reply-standard/` files (scripts, gate, gate test), the config key with its schema tests, the README and `/war-room` doc lines, and the version slots, no engine, guard, or agent surface changed in this window.
